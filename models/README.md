# โมเดลตรวจภาพ HelpMinths

ตำแหน่งที่ผู้ใช้ระบุคือ `models/parasite_yolo.pt` ยังไม่ได้รับไฟล์โมเดลจริงแยกจาก ZIP และยังไม่พบไฟล์นี้ใน GitHub ที่ตรวจ ณ วันที่ 3 พฤศจิกายน 2569 จึงไม่มี checkpoint ใน repository นี้ และยังไม่ได้ทดสอบ inference กับไฟล์ดังกล่าว

เมื่อมีไฟล์ YOLO **detection** ที่ฝึกแล้ว ให้วางไฟล์จริงในตำแหน่งนี้ API จะเลือกใช้โดยอัตโนมัติหากไม่ได้ตั้ง `HELPMINTHS_MODEL_PATH` เป็นค่าอื่น พาธเริ่มต้นอ้างจากรากโครงการ ไม่ขึ้นกับ directory ที่สั่งเริ่มเซิร์ฟเวอร์ การตั้งค่าพาธเองมีลำดับความสำคัญสูงกว่า และพาธที่ตั้งผิดจะไม่ถูกสลับไปโมเดลอื่นโดยเงียบ ๆ

สำหรับการรันนอก Docker ติดตั้ง `backend/requirements-model.txt` ด้วย runtime ที่ตรงกับ checkpoint ก่อนเริ่ม API ดูคำสั่งใน [คู่มือ backend](../backend/README.md) การมีไฟล์ชื่อ `.pt` เพียงอย่างเดียวไม่ยืนยันว่าเป็น YOLO detection หรือใช้ได้กับ runtime ที่ติดตั้ง

Dockerfile รองรับไฟล์ชื่อเดียวนี้ใน build context และจะติดตั้ง PyTorch/torchvision แบบ CPU กับส่วนประมวลผล YOLO เมื่อไฟล์นั้นมีอยู่ หากยังไม่มีไฟล์ จะใช้แอปแบบเบาตามเดิมและรายงานว่าโมเดลยังไม่พร้อม ไม่มีการดาวน์โหลด checkpoint อื่นมาแทน

ไฟล์โมเดลยังถูก Git ignore เพื่อไม่เพิ่ม binary โดยไม่ตั้งใจ หาก deploy จาก GitHub ไฟล์ที่มีเฉพาะในเครื่องจะไม่ติดไปกับ Render ต้องส่งมอบโมเดลจริงให้ build context เช่นไฟล์ที่อยู่ใน repository/ระบบ artifact ของผู้ดูแลตามวิธีเผยแพร่ที่เลือก การใช้ `git add -f models/parasite_yolo.pt` เป็นการนำโมเดลเข้า Git โดยชัดแจ้ง ไม่ควรทำกับชื่อไฟล์ตัวอย่างหรือไฟล์ที่ยังไม่มีอยู่

หลังติดตั้งและเริ่ม API ใหม่ ตรวจ `/api/health`: ต้องเป็น `model_ready: true` และ `model_name: parasite_yolo.pt` ก่อนทดสอบภาพจริง หน้าตรวจวินิจฉัยเดิมจะใช้ผลชื่อชนิด ความมั่นใจ และกรอบจากโมเดลผ่าน API โดยไม่ต้องอัปโหลด checkpoint ผ่านหน้าเว็บ ข้อมูลรุ่นโมเดลตรวจจาก SHA-256 ของไฟล์

การโหลดได้หรือการประมวลผลภาพได้ยังไม่ใช่ผลประเมินความแม่นยำ ต้องใช้ภาพพร้อมกรอบอ้างอิงที่ผู้เชี่ยวชาญตรวจแล้วเพื่อประเมินต่อ
