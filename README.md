# HelpMinths

เว็บภาษาไทยสำหรับสำรวจภาพไข่และตัวอ่อนพยาธิจากกล้องจุลทรรศน์ พร้อม Atlas 3D แบบอินเทอร์แอคทีฟ โทนเข้ม รองรับมือถือและคอมพิวเตอร์

## เผยแพร่บน Render

[เปิดหน้าสร้าง HelpMinths บน Render](https://render.com/deploy?repo=https://github.com/natchabuu-bit/helpminths)

ลิงก์นี้เป็นหน้าตรวจสอบและสร้างบริการในบัญชี Render ของคุณ ยังไม่ใช่ URL ของแอปที่เผยแพร่แล้ว

1. เข้าสู่ระบบ Render แล้วเปิดลิงก์ข้างต้น หากระบบขอเชื่อม GitHub ให้เลือก repository `natchabuu-bit/helpminths`
2. ตรวจรายการบริการ `helpminths` ซึ่งตั้งค่าเป็นแผน Free ใน `render.yaml` แล้วกด Deploy Blueprint หรือ Create New Resources ตามปุ่มที่แสดง
3. รอให้ build และ deploy เสร็จ เมื่อบริการแสดง Live ให้เปิด URL ที่ Render แสดงในหน้าบริการ ลิงก์นั้นจึงเป็นเว็บไซต์ที่เปิดจากมือถือได้

Blueprint ใช้ Docker ให้เว็บและ API อยู่ในบริการเดียว ตั้ง health check เป็น `/api/health` และปิดการ deploy อัตโนมัติจากการ push ครั้งถัดไป หากติดขั้นตอนเชื่อมบัญชี ให้ใช้หน้า Render โดยตรง ไม่ต้องส่งรหัสผ่านหรือ token ในแชต

หากมีเว็บไซต์บน Render อยู่แล้ว หลังอัปเดตโค้ดบน GitHub ให้เปิดหน้าบริการ → **Manual Deploy → Deploy latest commit** และรอให้สถานะเป็น Live เนื่องจากตั้ง `autoDeploy: false` การ build ในเครื่องคลาวด์นี้ยังไม่ได้อัปเดตเว็บไซต์สาธารณะ

การเผยแพร่ครั้งแรกเปิดใช้งานเว็บ Atlas และโหมดสาธิตได้ ส่วน AI ตรวจภาพจริงยังต้องเชื่อม trained weights ที่เข้ากันได้ตามหัวข้อโมเดลด้านล่าง

## ใช้งานโดยไม่ต่ออินเทอร์เน็ต

เว็บ production รองรับการเก็บไฟล์แอปสำหรับเปิดออฟไลน์ผ่าน service worker ต้องเปิดจาก HTTPS หรือ `localhost` โดยเตรียมบนมือถือแต่ละเครื่องดังนี้:

1. หลัง deploy เปิด URL เว็บไซต์ขณะมีอินเทอร์เน็ตอย่างน้อยหนึ่งครั้ง แล้วรอให้สถานะการเก็บเว็บสำหรับออฟไลน์พร้อมก่อนปิดหน้า
2. Android ใช้เมนูเบราว์เซอร์ → **ติดตั้งแอป / เพิ่มลงในหน้าจอหลัก**; iPhone/iPad เปิดด้วย Safari → **แชร์ → เพิ่มไปยังหน้าจอโฮม** ชื่อเมนูอาจต่างตามรุ่น หลังติดตั้งให้เปิดจากไอคอนขณะออนไลน์ และรอข้อความ **พร้อมใช้งานออฟไลน์** อีกครั้งก่อนปิดเน็ต เพราะพื้นที่เก็บของแอปที่ติดตั้งอาจแยกจากแท็บเบราว์เซอร์
3. เมื่อปิดอินเทอร์เน็ตแล้วเปิดเว็บที่เก็บไว้ จะใช้ Atlas, โหมดสาธิต และเลือกภาพจากเครื่องเพื่อดูภาพตัวอย่างได้ กล้องยังขึ้นกับสิทธิ์และความสามารถของอุปกรณ์

**การเก็บเว็บออฟไลน์ยังไม่ใช่การติดตั้ง AI ลงมือถือ** การตรวจภาพจริงใช้ API บนเซิร์ฟเวอร์ จึงใช้บริการบน Render ไม่ได้เมื่อมือถือไม่มีอินเทอร์เน็ต และ repository ยังไม่มี trained weights แม้ต่อเน็ตอยู่ก็ยังตรวจ AI จริงไม่ได้จนกว่าจะเชื่อมโมเดลที่รองรับ

แคชเก็บเฉพาะไฟล์เว็บ เช่น JavaScript, CSS, ฟอนต์ และภาพประกอบ ไม่เก็บภาพที่เลือกหรือคำตอบ API ประวัติผลตรวจอยู่ในหน่วยความจำของเซสชันและหายเมื่อรีเฟรชหรือปิดหน้า หากยังไม่เคยเปิดออนไลน์ การเก็บไฟล์ยังไม่สำเร็จ หรือเบราว์เซอร์ล้างพื้นที่จัดเก็บ ต้องเชื่อมอินเทอร์เน็ตเพื่อเตรียมใหม่ การเพิ่มไอคอนหน้าจอหลักเพียงอย่างเดียวไม่ได้ยืนยันว่าไฟล์ออฟไลน์พร้อมแล้ว

การตรวจ AI โดยไม่ใช้อินเทอร์เน็ตต้องเตรียม backend ในเครื่องหรือเครือข่ายภายใน พร้อม dependencies และ trained weights ที่เชื่อถือได้และทดสอบความเข้ากันได้ก่อน มือถือยังต้องเชื่อมถึง backend นั้นได้ อีกทางคือแปลงและเพิ่มโมเดลสำหรับประมวลผลในเบราว์เซอร์ ซึ่งยังไม่ได้พัฒนาในโปรเจกต์นี้

## เริ่มใช้งาน

ต้องใช้ Node.js 22.12+ หรือ 24 และ Python 3.12 ใช้ checkout ปัจจุบันได้เลย ไม่ต้องสร้าง Git worktree

```bash
cd /workspace/helpminths
bash scripts/install.sh
bash scripts/start.sh
```

Frontend พอร์ต 5173 จะส่ง `/api` ไปยัง FastAPI พอร์ต 8000 ผ่าน Vite proxy ในเครื่องเดียวกัน ต้องเปิดทั้งสองบริการ กระบวนการที่รันอยู่จะไม่ติดไปกับ snapshot เมื่อเริ่มเครื่องใหม่ให้รัน `bash scripts/start.sh` อีกครั้ง ใช้ HTTPS สำหรับการเปิดจากมือถือผ่านบริการโฮสต์

## เปิดจากมือถือหรือเผยแพร่เป็นเว็บไซต์

พาธไฟล์ในเครื่องคลาวด์และลิงก์คู่มือ README ไม่ใช่ URL เว็บไซต์สาธารณะ การ Publish สภาพแวดล้อม Codex เก็บสภาพแวดล้อมพัฒนา แต่ไม่ได้เผยแพร่ HelpMinths เป็นเว็บโฮสต์

เตรียม production ให้ frontend และ API อยู่ภายใต้เว็บไซต์เดียวกันได้แล้ว:

```bash
npm run build
PORT=8080 bash scripts/start-production.sh
```

คำสั่งนี้ใช้เว็บที่ build แล้ว ไม่ต้องเปิด Vite ควบคู่ เหมาะสำหรับนำไปตั้งค่าบนบริการโฮสต์ที่มี HTTPS และ public ingress ของตัวเอง ค่า `PORT` ต้องตรงกับที่โฮสต์กำหนด

สำหรับบริการที่รองรับ Docker:

```bash
docker build -t helpminths .
docker run --rm -p 8080:8000 helpminths
```

Dockerfile ไม่รวมไฟล์โมเดล รหัสลับ หรือภาพของผู้ใช้ การตรวจ AI จริงยังต้องติดตั้ง runtime ของโมเดลและเชื่อม trained weights แยกต่างหาก Dockerfile เป็น configuration สำหรับ deployment; อ่านรายงานการทดสอบปัจจุบันก่อนถือว่า image ได้ build ในเครื่องใดแล้ว

สถานะตรวจสอบ: production แบบรันตรงผ่าน browser tests 6/6 และ backend tests 15/15 และ build Docker image พร้อมทดสอบ HTML, JS/CSS, API health และการจัดการไฟล์อัปโหลดผ่านแล้ว ในคลาวด์นี้ใช้การตั้งค่า proxy DNS และ CA ของแพลตฟอร์มชั่วคราวระหว่าง build โดยยังตรวจ TLS และไม่เก็บ credentials หรือ CA secret ใน image ส่วน Dockerfile สำหรับ Render ไม่ต้องใช้การตั้งค่าเฉพาะคลาวด์นี้ การบันทึกโค้ดบน GitHub ยังไม่ใช่การสร้างบริการหรือยืนยันว่าเว็บไซต์บน Render เป็น Live แล้ว

การสมัครบัญชี Render ไม่ได้สร้างบริการหรือเชื่อมบัญชีกับเครื่องมือในแชตโดยอัตโนมัติ ใช้ลิงก์ Blueprint ด้านบนเพื่อสร้างบริการในบัญชีของคุณ แล้วใช้ URL ที่ Render ออกให้ ไม่ต้องซื้อโดเมนหรือส่งรหัสผ่านและ access token ในแชต

## ฟีเจอร์

- เลือกภาพ JPEG, PNG หรือ WebP สูงสุด 20 MB จากเครื่อง หรือเปิดกล้องมือถือผ่าน file input `capture="environment"` การเปิดกล้องขึ้นอยู่กับเบราว์เซอร์/อุปกรณ์
- ลากวางภาพ ตรวจตำแหน่งด้วยกรอบรายฟอง เลือกผล ปรับตัวกรองความมั่นใจ และดาวน์โหลดรายงาน JSON
- Atlas ไข่พยาธิอ้างอิง 11 กลุ่มที่โครงการให้ความสำคัญสำหรับไทย: Ascaris, Trichuris, Hookworm, Opisthorchis viverrini (OV), Taenia spp., Enterobius, พยาธิใบไม้ลำไส้ขนาดเล็ก (MIF), Hymenolepis nana (ตืดแคระ), H. diminuta (ตืดหนู), Echinostoma spp. (ตัวอย่างกลุ่มใบไม้ลำไส้ขนาดกลาง) และ Fasciolopsis buski (ใบไม้ลำไส้ขนาดใหญ่) หมุน ซูม หยุดหมุน รีเซ็ต ดูภาพตัดภายใน และค้นหาจุดสังเกต พร้อมภาพ SVG สำรองเมื่อไม่มี WebGL ชื่อขนาดกลาง/ใหญ่ใช้กับกลุ่มตัวเต็มวัย ไม่ใช่เกณฑ์แยกไข่จากขนาดเพียงอย่างเดียว
- เพิ่ม Strongyloides stercoralis ระยะ rhabditiform เป็นกลุ่มอ้างอิงที่ 12 โดยเน้น genital primordium ภายในลำตัวให้กดขยายดูได้ พร้อมช่องปากสั้น หลอดอาหาร ลำไส้ และหางแหลม รวม 6 จุด เทียบกับตัวอ่อน rhabditiform ของพยาธิปากขอ ดู [หลักฐาน Strongyloides](docs/atlas/strongyloides-evidence.md)
- โหมดเทียบภาพกล้องจุลทรรศน์จริงกับ 3D: ภาพ 11 ภาพครอบคลุม 9 กลุ่ม พร้อมเครดิต Thomas P. Buckelew และ CC BY-NC 4.0 สำหรับการศึกษาไม่ใช่เชิงพาณิชย์ ซูม/ลากภาพจริงแยกจากโมเดลได้ รวมภาพไว้ในชุดออฟไลน์ ส่วน OV, MIF และ Echinostoma แสดงสถานะรอภาพที่ยืนยันชนิดและสิทธิ์ ภาพตัวอ่อน Strongyloides ใช้ดูภาพรวมและยังไม่ยืนยัน genital primordium จากภาพนั้น
- เลือกโครงสร้าง 57 รายการตามระยะจากโมเดลหรือรายการ เพื่อไฮไลต์ โฟกัส เปิดภาพตัด และอ่านคำอธิบายไทยพร้อมแหล่งอ้างอิง แบบจำลองแสดงกายวิภาคไข่และตัวอ่อนตามระยะ ไม่เติมออร์แกเนลล์ที่ไม่มีหลักฐาน ดู [หลักฐานและสิทธิ์ภาพ Atlas](docs/atlas/README.th.md)
- Ascaris เลือกไข่ไม่ปฏิสนธิ ไข่ปฏิสนธิระยะต้น ระยะแบ่งเซลล์ และไข่มีตัวอ่อนได้ พร้อมภาพวาดอธิบายและโมเดลที่สอดคล้องกัน มีสวิตช์ decorticated แยกจากระยะพัฒนา ภาพจริงใช้สองไฟล์เดิมตามคำบรรยายต้นทาง; cleavage/decorticated ยังใช้ภาพวาดที่ติดป้ายชัดเจน ดู [หลักฐานระยะไข่ Ascaris](docs/atlas/ascaris-stages-evidence.md)
- ประวัติผลตรวจในหน่วยความจำของเซสชันปัจจุบัน ล้างเมื่อรีเฟรชหรือปิดหน้า บริการ API ไม่จัดเก็บภาพถาวร
- โหมดสาธิตแยกชัดเจนว่าเป็นภาพวาดและข้อมูลจำลอง ไม่ใช่ผลตรวจจาก AI

## สถานะโมเดลและ dataset

รายการแหล่งข้อมูลสำหรับฝึกโมเดลตามขอบเขต 11 กลุ่ม สิทธิ์ใช้ และแผนทดสอบกับภาพจริงอยู่ใน [รายงานคัดเลือก dataset](docs/datasets/README.th.md) และ [ทะเบียนแหล่งข้อมูล CSV](docs/datasets/dataset_catalog.csv) ปรับเมื่อ 19 ตุลาคม 2026 โดยเพิ่ม MIF, ตืดแคระ, ตืดหนู, Echinostoma spp. และ Fasciolopsis buski จากขอบเขตเดิม 6 กลุ่มที่มี OV และพัก Schistosoma ทั้งสามชนิดไว้; เป็นการจัดลำดับงานของโครงการ ไม่ใช่ข้อสรุปว่าไม่มี Schistosoma ในไทย

Chula-ParasiteEgg-11 มีชื่อคลาสที่เป็น candidate 9/11 กลุ่มตามขอบเขตไข่เดิม รวม H. nana, H. diminuta และ F. buski แต่ยังไม่พบคลาส MIF หรือ Echinostoma ใน configuration ที่ตรวจ คำว่า 11 ของชื่อ dataset จึงไม่ได้หมายถึงทุกกลุ่มใน Atlas ปัจจุบัน LIDS–UNICAMP เสริมได้ 7/11 กลุ่มในขอบเขตเดิม รวมภาพเป้าหมาย 1,646 ภาพ โดยยังต้องยืนยันสิทธิ์และ provenance ก่อนฝึก Strongyloides ที่เพิ่มใน Atlas ยังไม่ได้เพิ่มข้อมูลฝึกหรือคลาสของโมเดลโดยอัตโนมัติ

ชื่อ OV ต้นทางคือ `Opisthorchis viverrine` ต้องตรวจ annotation และให้ผู้เชี่ยวชาญยืนยัน mapping เป็น O. viverrini ภาพไข่ OV/MIF/Clonorchis และไข่ Echinostoma/Fasciolopsis/Fasciola อาจคล้ายกัน จึงต้องมีตัวอย่างแยกโรคและ reference standard ที่เหมาะสม หากหลักฐานไม่พอให้รายงานลักษณะไข่ไม่แน่ชัดและยืนยันเพิ่ม ไม่แบ่งชนิดจากขนาดเพียงอย่างเดียว และไม่ map Fasciola (ใบไม้ตับ) เป็น Fasciolopsis (ใบไม้ลำไส้) การพบชื่อคลาสในแหล่งข้อมูลหรือการเพิ่ม Atlas ไม่ได้ยืนยันว่า AI ของแอพตรวจได้แล้ว

เริ่มจากภาพของห้องปฏิบัติการได้ตาม [คู่มือเตรียมภาพ 3 ภาพแรกและแผนฝึกโมเดล](docs/training/TRAIN.th.md) โดยทำกรอบให้ผู้เชี่ยวชาญยืนยันก่อน รอบ 3 ภาพนี้ใช้ทดลองเตรียมข้อมูล ไม่ใช้สรุปความแม่นยำของโมเดลกับภาพใหม่

ใช้ [เครื่องมือตรวจกรอบออฟไลน์](tools/review/README.th.md) เพื่อเลือกภาพจากเครื่อง ตรวจ/แก้กรอบ และส่งออก JSON ได้ ตัวเครื่องมือที่เผยแพร่ไม่มีภาพของผู้ใช้และไม่อัปโหลดภาพผ่านเครือข่าย

แหล่งอ้างอิงที่ผู้ใช้ให้: [Kaggle notebook](https://www.kaggle.com/code/mohaliy2016/ai4ntd-kk2-0-p1-5-sth-schm-v2-notebook)

**ยังไม่มี trained weights ใน repository นี้** ไฟล์ notebook ที่แนบมีขนาดเกินขีดจำกัด 32 MiB ของเครื่องมือ และการอ่าน Kaggle จากเครื่องคลาวด์ถูก network proxy ปฏิเสธในรอบสร้าง จึงยังยืนยันสถาปัตยกรรม รายชื่อคลาส dataset หรือประสิทธิภาพของโมเดลต้นฉบับไม่ได้ Atlas เป็นคลังอ้างอิงแยกจากคลาสของโมเดล

API มี adapter เสริมสำหรับ **Ultralytics YOLO detection `.pt` ที่ฝึกแล้ว** นี่เป็นรูปแบบที่ระบบรองรับ ไม่ใช่ข้อยืนยันว่า notebook ที่ให้มาใช้ YOLO หากต้นฉบับใช้รูปแบบอื่น ต้องเพิ่ม adapter ให้ตรงกับโมเดลก่อน

เชื่อมโมเดลที่ทราบแหล่งที่มาและเชื่อถือได้:

```bash
cd /workspace/helpminths
.venv/bin/python -m pip install -r backend/requirements-model.txt
# วาง best.pt ของโปรเจกต์ไว้ใน models/ โดยไม่เพิ่มไฟล์ใหญ่ลง Git
export HELPMINTHS_MODEL_PATH=/workspace/helpminths/models/best.pt
bash scripts/start.sh
```

ชื่อคลาสดึงจาก `model.names` โดยตรง ไม่มีการเดาชื่อชนิดหรือใช้โมเดล COCO ทั่วไปแทนโมเดลไข่พยาธิ เมื่อไม่มีโมเดล `/api/health` จะตอบ `model_ready: false` และการส่งภาพตรวจจริงจะได้รับ HTTP 503 พร้อมคำอธิบาย ไม่ได้สร้างผลตรวจปลอม

`HELPMINTHS_MODEL_PATH` เป็นพาธไฟล์ในเครื่อง ไม่ใช่รหัสลับ ตั้งค่าผ่าน environment ก่อนเริ่ม API แล้วรีสตาร์ตบริการ ต้องตรวจความเข้ากันได้ของโมเดลและชุดทดสอบจริงก่อนใช้ในงานคัดกรอง ผลจาก AI ไม่ใช่การวินิจฉัยทางคลินิกและต้องให้ผู้เชี่ยวชาญยืนยัน

## การตรวจสอบ

```bash
npm run build
.venv/bin/python -m pytest backend/tests -q
curl --fail http://127.0.0.1:8000/api/health
```

Backend tests ตรวจไฟล์ไม่ถูกต้อง ขนาดภาพ ขนาดไฟล์ EXIF orientation ชื่อคลาสและขอบเขตกรอบ โดยใช้ตัวทดสอบแทน predictor เฉพาะ unit test ไม่ใช่การยืนยันความแม่นยำโมเดลจริง

Browser tests ใช้ Playwright โดยเปิดเว็บและ API ด้วย `bash scripts/start.sh` ไว้ก่อน แล้วรัน `npm run test:e2e` ในอีกเทอร์มินัล ถ้ามี Chromium ที่ `/usr/bin/chromium` จะใช้ได้เลย หรือกำหนด `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`; เครื่องอื่นติดตั้งด้วย `npx playwright install chromium` ก่อน ชุดทดสอบตรวจ workflow จริงกับข้อมูลสาธิต และทดสอบสัญญา API ด้วย response จำลองหนึ่งกรณี โดยไม่อ้างว่าเป็นผลจากโมเดลจริง

ทดสอบออฟไลน์กับ production build โดยเปิดบริการไว้ก่อน:

```bash
npm run build
PORT=8081 bash scripts/start-production.sh
```

จากอีกเทอร์มินัลรัน `HELPMINTHS_TEST_URL=http://127.0.0.1:8081 npm run test:offline` ชุดทดสอบนี้เตรียมแคชขณะออนไลน์ แล้วตัดเครือข่ายในเบราว์เซอร์เพื่อตรวจการเปิดหน้าใหม่และฟีเจอร์ออฟไลน์ ไม่ได้ยืนยันว่าโมเดล AI พร้อมใช้งาน

ดูสัญญา API และรายละเอียดการติดตั้งที่ [backend/README.md](backend/README.md)

## เทคโนโลยี

React 19 + TypeScript + Vite, Three.js / React Three Fiber, FastAPI + Pillow ฟอนต์ Noto Sans Thai และ Inter ติดตั้งในโปรเจกต์และไม่ต้องเรียกเว็บฟอนต์ภายนอก

แบบจำลอง Atlas เป็นภาพอธิบาย morphology ไม่ใช่ภาพถ่ายหรือโครงสร้างสแกน และไม่ใช้สเกลเทียบกันระหว่างชนิด เนื้อหาอ้างอิงรูปแบบลักษณะทั่วไปจาก CDC DPDx โปรดตรวจเอกสารปฐมภูมิและให้ผู้เชี่ยวชาญทบทวนก่อนใช้สอนหรืออ้างอิงทางคลินิก
