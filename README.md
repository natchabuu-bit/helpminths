# HelpMinths AI

เว็บภาษาไทยสำหรับสำรวจภาพไข่และตัวอ่อนพยาธิจากกล้องจุลทรรศน์ พร้อม Atlas 3D แบบอินเทอร์แอคทีฟ ธีมสว่างสไตล์โมเดิร์น ตัวอักษรขนาดใหญ่ รองรับมือถือและคอมพิวเตอร์

หน้าตารุ่นใหม่ใช้แนวแผงเครื่องมือวิทยาศาสตร์จากตัวอย่าง Medusa JF-4 ที่เจ้าของแนบมา: พื้น aqua สว่าง ตัวอักษร teal และจุดเน้น coral หน้าหลักเลือกสำรวจ OV/Ascaris/Taenia ผ่านโมเดล 3D เดิมได้ มีภาพตัด การหมุน ซูม คืนมุมมอง และคำอธิบายโครงสร้าง มือถือมีปุ่มอัปโหลดทันที รวมทั้งภาพวาด 2D เมื่อ WebGL ไม่พร้อม และเคารพการตั้งค่าลดการเคลื่อนไหว เมนูตรวจภาพ Atlas ภาพจริง Dashboard ประวัติ บัญชี รายงาน และ SUS ใช้ข้อมูลเดิม จำนวนกลุ่มใน Atlas แยกจากสถานะโมเดลตรวจภาพจริง

ตรวจหน้าตาและการโต้ตอบเพิ่มด้วย `HELPMINTHS_TEST_URL=http://127.0.0.1:8088 npm run test:interface` เมื่อเปิดเว็บ production ในเครื่องแล้ว คำสั่ง `node scripts/capture-interface.mjs` บันทึกภาพตัวอย่าง desktop/mobile จากบริการสาธารณะในเครื่องไปยัง `/tmp/helpminths-interface-previews` และปฏิเสธบริการที่เปิดบัญชีหรือใช้ข้อมูลทดสอบคลินิก

รุ่นแพลตฟอร์มเพิ่มสมัครสมาชิกและแก้บัญชีด้วยตนเอง การตรวจคุณภาพภาพ ประวัติรายวัน คลังส่งต่อผู้เชี่ยวชาญที่ยืนยันรหัสผ่านซ้ำ PDF/CSV, Dashboard จากฐานข้อมูล และ feedback คุณภาพโมเดล อ่าน [คู่มือตั้งค่าแพลตฟอร์ม](docs/platform/README.th.md) ก่อนเปิดใช้การเก็บข้อมูลจริง

**Repository ไม่มี trained weights บัญชีเริ่มต้น ผลตรวจ หรือคะแนนความแม่นยำที่เตรียมไว้** รุ่น Docker/Render เปิดฐานข้อมูลส่วนตัวอัตโนมัติด้วย `HELPMINTHS_AUTO_STORAGE=1` จึงสมัครคำขอจากหน้าบัญชีและเข้าสู่ระบบได้หลัง Super Admin อนุมัติ; การรัน API นอก Docker เลือกตั้งพาธส่วนตัวเองได้ ไม่มีโมเดลจะแสดง Not configured การประเมินโมเดลต้องมี ground truth อิสระที่ผ่านการตรวจแล้ว ไม่สร้างผลทดแทนส่วนที่ยังขาด

อ่าน [วิธีเปิด Super Admin อนุมัติสมาชิกและตรวจยืนยัน](docs/platform/SUPER-ADMIN-AND-EXPERTS.th.md) และ [วิธีเปิดบัญชี ส่งต่อภาพ และเก็บข้อมูลถาวร](docs/platform/ACCOUNTS-AND-REFERRALS.th.md) ก่อนใช้งานจริง **Render Free ปัจจุบันไม่มีพื้นที่เก็บถาวร** รุ่นนี้เปิดใช้บัญชี/ประวัติบนพื้นที่ชั่วคราวได้ทันที ข้อมูลอาจหายเมื่อ restart หรือ deploy การเก็บระยะยาวต้องเชื่อม volume หรือใช้เครื่องตนเอง

## เผยแพร่บน Render

[เปิดหน้าสร้าง HelpMinths บน Render](https://render.com/deploy?repo=https://github.com/natchabuu-bit/helpminths)

ลิงก์นี้เป็นหน้าตรวจสอบและสร้างบริการในบัญชี Render ของคุณ ยังไม่ใช่ URL ของแอปที่เผยแพร่แล้ว

1. เข้าสู่ระบบ Render แล้วเปิดลิงก์ข้างต้น หากระบบขอเชื่อม GitHub ให้เลือก repository `natchabuu-bit/helpminths`
2. ตรวจรายการบริการ `helpminths` ซึ่งตั้งค่าเป็นแผน Free ใน `render.yaml` แล้วกด Deploy Blueprint หรือ Create New Resources ตามปุ่มที่แสดง
3. รอให้ build และ deploy เสร็จ เมื่อบริการแสดง Live ให้เปิด URL ที่ Render แสดงในหน้าบริการ ลิงก์นั้นจึงเป็นเว็บไซต์ที่เปิดจากมือถือได้

Blueprint ใช้ Docker ให้เว็บและ API อยู่ในบริการเดียว ตั้ง health check เป็น `/api/health` และปิดการ deploy อัตโนมัติจากการ push ครั้งถัดไป หากติดขั้นตอนเชื่อมบัญชี ให้ใช้หน้า Render โดยตรง ไม่ต้องส่งรหัสผ่านหรือ token ในแชต

หากมีเว็บไซต์บน Render อยู่แล้ว หลังอัปเดตโค้ดบน GitHub ให้เปิดหน้าบริการ → **Manual Deploy → Deploy latest commit** และรอให้สถานะเป็น Live เนื่องจากตั้ง `autoDeploy: false` การ build ในเครื่องคลาวด์นี้ยังไม่ได้อัปเดตเว็บไซต์สาธารณะ

การเผยแพร่ครั้งแรกเปิดใช้งานเว็บ Atlas และโหมดสาธิตได้ ส่วน AI ตรวจภาพจริงยังต้องเชื่อม trained weights ที่เข้ากันได้ตามหัวข้อโมเดลด้านล่าง

Blueprint แผน Free ยังไม่เชื่อมพื้นที่ถาวร Dockerfile ดาวน์โหลดโมเดลจากแหล่งที่เจ้าของเลือกใน `models/source.json` แล้วติดตั้ง YOLO runtime แบบ CPU และทดสอบการประมวลผลก่อน deploy บัญชีใช้งานได้บนพื้นที่ชั่วคราวทันที ส่วนการเก็บผลระยะยาวต้องเลือกโฮสต์/แผนที่รองรับ persistent volume ตั้ง `HELPMINTHS_DATA_DIR` ไปยัง volume แล้วสร้างผู้ดูแลผ่าน CLI หรือ host setup token ตามคู่มือ (ผู้ใช้ทั่วไปสมัครเองจากเว็บได้) การตั้ง `HELPMINTHS_STORAGE_DURABLE=1` เป็นเพียงคำประกาศผู้ดูแล ไม่ได้สร้าง disk หรือสำรองข้อมูล อ่านขั้นตอนในคู่มือแพลตฟอร์ม อย่าเก็บข้อมูลจริงไว้บน filesystem ชั่วคราวของ Render

## ใช้งานโดยไม่ต่ออินเทอร์เน็ต

เว็บ production รองรับการเก็บไฟล์แอปสำหรับเปิดออฟไลน์ผ่าน service worker ต้องเปิดจาก HTTPS หรือ `localhost` โดยเตรียมบนมือถือแต่ละเครื่องดังนี้:

1. หลัง deploy เปิด URL เว็บไซต์ขณะมีอินเทอร์เน็ตให้โหลดไฟล์เว็บครบก่อนปิดหน้า รุ่นนี้ไม่มีแถบสถานะออฟไลน์ จึงควรลองเปิด Atlas และโหมดสาธิตเมื่อปิดเน็ตเพื่อยืนยันว่าเครื่องนั้นเก็บไฟล์สำเร็จ
2. Android ใช้เมนูเบราว์เซอร์ → **ติดตั้งแอป / เพิ่มลงในหน้าจอหลัก**; iPhone/iPad เปิดด้วย Safari → **แชร์ → เพิ่มไปยังหน้าจอโฮม** ชื่อเมนูอาจต่างตามรุ่น หลังติดตั้งให้เปิดจากไอคอนขณะออนไลน์และลองเปิดแบบออฟไลน์อีกครั้ง เพราะพื้นที่เก็บของแอปที่ติดตั้งอาจแยกจากแท็บเบราว์เซอร์
3. เมื่อปิดอินเทอร์เน็ตแล้วเปิดเว็บที่เก็บไว้ จะใช้ Atlas, โหมดสาธิต และเลือกภาพจากเครื่องเพื่อดูภาพตัวอย่างได้ กล้องยังขึ้นกับสิทธิ์และความสามารถของอุปกรณ์

**การเก็บเว็บออฟไลน์ยังไม่ใช่การติดตั้ง AI ลงมือถือ** การตรวจภาพจริงใช้ API บนเซิร์ฟเวอร์ จึงใช้บริการบน Render ไม่ได้เมื่อมือถือไม่มีอินเทอร์เน็ต และ repository ยังไม่มี trained weights แม้ต่อเน็ตอยู่ก็ยังตรวจ AI จริงไม่ได้จนกว่าจะเชื่อมโมเดลที่รองรับ

แคชเก็บเฉพาะไฟล์เว็บ เช่น JavaScript, CSS, ฟอนต์ และภาพประกอบ ไม่เก็บภาพส่วนตัวหรือคำตอบ API เมื่อเปิดระบบบัญชี ประวัติบนเซิร์ฟเวอร์ การเข้าสู่ระบบ คลังภาพส่งต่อและรายงานต้องเชื่อม backend ส่วนผลชั่วคราวในโหมดที่ยังไม่ตั้งฐานข้อมูลและข้อมูลสาธิตอยู่ในหน่วยความจำและหายเมื่อรีเฟรชหรือปิดหน้า หากยังไม่เคยเปิดออนไลน์ การเก็บไฟล์ยังไม่สำเร็จ หรือเบราว์เซอร์ล้างพื้นที่จัดเก็บ ต้องเตรียมใหม่ การเพิ่มไอคอนหน้าจอหลักเพียงอย่างเดียวไม่ได้ยืนยันว่าไฟล์ออฟไลน์พร้อมแล้ว

การตรวจ AI โดยไม่ใช้อินเทอร์เน็ตต้องเตรียม backend ในเครื่องหรือเครือข่ายภายใน พร้อม dependencies และ trained weights ที่เชื่อถือได้และทดสอบความเข้ากันได้ก่อน มือถือยังต้องเชื่อมถึง backend นั้นได้ อีกทางคือแปลงและเพิ่มโมเดลสำหรับประมวลผลในเบราว์เซอร์ ซึ่งยังไม่ได้พัฒนาในโปรเจกต์นี้

## เริ่มใช้งาน

ต้องใช้ Node.js 22.12+ หรือ 24 และ Python 3.12 ใช้ checkout ปัจจุบันได้เลย ไม่ต้องสร้าง Git worktree

```bash
cd /workspace/helpminths
bash scripts/install.sh
bash scripts/start.sh
```

Frontend พอร์ต 5173 จะส่ง `/api` ไปยัง FastAPI พอร์ต 8000 ผ่าน Vite proxy ในเครื่องเดียวกัน ต้องเปิดทั้งสองบริการ กระบวนการที่รันอยู่จะไม่ติดไปกับ snapshot เมื่อเริ่มเครื่องใหม่ให้รัน `bash scripts/start.sh` อีกครั้ง ใช้ HTTPS สำหรับการเปิดจากมือถือผ่านบริการโฮสต์

## เปิดจากมือถือหรือเผยแพร่เป็นเว็บไซต์

พาธไฟล์ในเครื่องคลาวด์และลิงก์คู่มือ README ไม่ใช่ URL เว็บไซต์สาธารณะ การ Publish สภาพแวดล้อม Codex เก็บสภาพแวดล้อมพัฒนา แต่ไม่ได้เผยแพร่ HelpMinths เป็นเว็บโฮสต์

เตรียม production ให้ frontend และ API อยู่ภายใต้เว็บไซต์เดียวกันได้แล้ว:

```bash
npm run build
PORT=8080 bash scripts/start-production.sh
```

คำสั่งนี้ใช้เว็บที่ build แล้ว ไม่ต้องเปิด Vite ควบคู่ เหมาะสำหรับนำไปตั้งค่าบนบริการโฮสต์ที่มี HTTPS และ public ingress ของตัวเอง ค่า `PORT` ต้องตรงกับที่โฮสต์กำหนด

สำหรับบริการที่รองรับ Docker:

```bash
docker build -t helpminths .
docker run --rm -p 8080:8000 helpminths
```

Dockerfile ไม่รวมรหัสลับหรือภาพผู้ใช้ ค่าเริ่มต้นจะดึง ZIP/โมเดลจาก Google Drive ที่เจ้าของเลือกใน `models/source.json` เลือก checkpoint และติดตั้งเป็น `models/parasite_yolo.pt` พร้อม CPU runtime แล้วตรวจว่าประมวลผลภาพสังเคราะห์ได้ก่อน deploy หากต้องการรุ่นไม่มีโมเดล ให้ build ด้วย `--build-arg HELPMINTHS_FETCH_MODEL=0` อย่างชัดแจ้ง อ่าน [วิธีติดตั้งและตรวจสถานะโมเดล](models/README.md) รวมถึงข้อจำกัดการตรวจแหล่งจริงก่อนถือว่าใช้งานได้

ผลทดสอบของแพลตฟอร์มและขอบเขตหลักฐานอยู่ใน [รายงานการตรวจสอบ](docs/platform/VALIDATION.md) การบันทึกโค้ดบน GitHub ยังไม่ใช่การยืนยันว่าเว็บไซต์บน Render deploy รุ่นล่าสุดแล้ว และการผ่านการทดสอบซอฟต์แวร์ไม่ได้ยืนยันความแม่นยำของ YOLO จริง

การสมัครบัญชี Render ไม่ได้สร้างบริการหรือเชื่อมบัญชีกับเครื่องมือในแชตโดยอัตโนมัติ ใช้ลิงก์ Blueprint ด้านบนเพื่อสร้างบริการในบัญชีของคุณ แล้วใช้ URL ที่ Render ออกให้ ไม่ต้องซื้อโดเมนหรือส่งรหัสผ่านและ access token ในแชต

## Dashboard โครงการ กพด. เขตสุขภาพที่ 2

เมนู **Dashboard** (`/#dashboard`) ใช้รูปแบบจาก `helminth-dashboard (1).zip` ของเจ้าของ: หัวสรุปสีเขียวเข้ม/ทอง วงแหวนความครอบคลุม กราฟกระจายรายโรงเรียน กราฟอำเภอ/สังกัด/ชนิดพยาธิ และช่วงร้อยละที่เลือกกรองทั้งหน้าได้ เลือกปี **2568–2569** ค้นหาชื่อโรงเรียนหรือตำบลในภาพรวม ดูรายชื่อ 169/170 แห่งพร้อมตำบลและชนิดที่พบ เรียงตารางและดาวน์โหลด CSV ได้ รายการติดตามใช้เกณฑ์ส่งตรวจตั้งแต่ 30 คน

เพิ่มการเปรียบเทียบสองปี: KPI 5 รายการ กราฟแท่งคู่ โรงเรียนจับคู่ 167 แห่ง และอันดับร้อยละเพิ่ม/ลดที่ส่งตรวจตั้งแต่ 30 คนทั้งสองปี พร้อม **แนวโน้มปี 2557–2569** กราฟเส้นซ่อน/แสดงได้ ตารางสี และส่วนแบ่งชนิดพยาธิที่ระบุตัวหารชัดเจน อ่าน [วิธีใช้หลายปีและข้อจำกัดของแหล่งข้อมูล](docs/surveys/MULTI_YEAR.th.md)

ปี 2569 ใช้ Excel ที่ตรวจยอดแล้ว: ส่งตรวจ 15,888 คน ตรวจพบตามรายงาน 698 คน (4.39%) คงรายการรอข้อมูล ช่องว่าง และเข็มหมุดขัดกันไว้ให้ตรวจทาน ปี 2568 และรายงานเก่าใช้ JSON ที่เจ้าของแนบ ซึ่งยังไม่มี workbook ต้นฉบับปีเก่าสำหรับตรวจเทียบ ระบุแหล่งที่มาและข้อสังเกตไว้ในหน้าเว็บ ไม่รวมจำนวนคนข้ามปีหรือสร้างตัวหารที่ไม่มี

ข้อมูลเป็น **รุ่นนำเข้า ไม่ใช่การเชื่อมต่อสด** เผยแพร่เฉพาะข้อมูลสรุประดับพื้นที่และโรงเรียนตามคำขอ ไม่มี Excel ดิบ หมายเหตุส่วนตัว หรือข้อมูลรายบุคคล อัปเดตโดย [นำเข้าใหม่แล้ว deploy](docs/surveys/IMPORTING.md) ค่า `HELPMINTHS_DASHBOARD_SOURCE=auto` หรือ `snapshot` ใช้ชุดนำเข้า สามารถเลือก `google_sheets` เพื่อใช้ [ตัวเชื่อม Google](docs/sheets-dashboard.md) ที่ตรวจอัปเดตทุก 30 วินาที การ push โค้ดยังไม่ deploy Render โดยอัตโนมัติ

## ฟีเจอร์

- เลือกไฟล์ภาพได้ทุกนามสกุลโดยตรวจข้อมูลจริง รองรับ JPEG/PNG/WebP/HEIC/HEIF/AVIF/TIFF/BMP/GIF และภาพราสเตอร์อื่นตามตัวถอดรหัส สูงสุด 20 MiB/40 ล้านพิกเซล; SVG/PDF/RAW และ TIFF 32-bit ต้องแปลงก่อน เปิดกล้องผ่าน `capture="environment"` ได้ตามอุปกรณ์
- ลากวางภาพ ตรวจกรอบรายฟอง เลือกผล ปรับตัวกรองความมั่นใจ และบันทึกผลเข้าประวัติรายวันเมื่อเข้าสู่ระบบ นำปุ่มส่งออกรายงาน JSON ออกแล้ว
- Atlas ไข่พยาธิอ้างอิง 11 กลุ่มที่โครงการให้ความสำคัญสำหรับไทย: Ascaris, Trichuris, Hookworm, Opisthorchis viverrini (OV), Taenia spp., Enterobius, พยาธิใบไม้ลำไส้ขนาดเล็ก (MIF), Hymenolepis nana (ตืดแคระ), H. diminuta (ตืดหนู), Echinostoma spp. (ตัวอย่างกลุ่มใบไม้ลำไส้ขนาดกลาง) และ Fasciolopsis buski (ใบไม้ลำไส้ขนาดใหญ่) หมุน ซูม หยุดหมุน รีเซ็ต ดูภาพตัดภายใน และค้นหาจุดสังเกต พร้อมภาพ SVG สำรองเมื่อไม่มี WebGL ชื่อขนาดกลาง/ใหญ่ใช้กับกลุ่มตัวเต็มวัย ไม่ใช่เกณฑ์แยกไข่จากขนาดเพียงอย่างเดียว
- เพิ่ม Strongyloides stercoralis ระยะ rhabditiform เป็นกลุ่มอ้างอิงที่ 12 โดยเน้น genital primordium ภายในลำตัวให้กดขยายดูได้ พร้อมช่องปากสั้น หลอดอาหาร ลำไส้ และหางแหลม รวม 6 จุด เทียบกับตัวอ่อน rhabditiform ของพยาธิปากขอ ดู [หลักฐาน Strongyloides](docs/atlas/strongyloides-evidence.md)
- โหมดเทียบภาพกล้องจุลทรรศน์จริงกับ 3D: ภาพ 11 ภาพครอบคลุม 9 กลุ่ม พร้อมเครดิต Thomas P. Buckelew และ CC BY-NC 4.0 สำหรับการศึกษาไม่ใช่เชิงพาณิชย์ ซูม/ลากภาพจริงแยกจากโมเดลได้ รวมภาพไว้ในชุดออฟไลน์ ส่วน OV, MIF และ Echinostoma แสดงสถานะรอภาพที่ยืนยันชนิดและสิทธิ์ ภาพตัวอ่อน Strongyloides ใช้ดูภาพรวมและยังไม่ยืนยัน genital primordium จากภาพนั้น
- เลือกโครงสร้าง 57 รายการตามระยะจากโมเดลหรือรายการ เพื่อไฮไลต์ โฟกัส เปิดภาพตัด และอ่านคำอธิบายไทยพร้อมแหล่งอ้างอิง แบบจำลองแสดงกายวิภาคไข่และตัวอ่อนตามระยะ ไม่เติมออร์แกเนลล์ที่ไม่มีหลักฐาน ดู [หลักฐานและสิทธิ์ภาพ Atlas](docs/atlas/README.th.md)
- Ascaris เลือกไข่ไม่ปฏิสนธิ ไข่ปฏิสนธิระยะต้น ระยะแบ่งเซลล์ และไข่มีตัวอ่อนได้ พร้อมภาพวาดอธิบายและโมเดลที่สอดคล้องกัน มีสวิตช์ decorticated แยกจากระยะพัฒนา ภาพจริงใช้สองไฟล์เดิมตามคำบรรยายต้นทาง; cleavage/decorticated ยังใช้ภาพวาดที่ติดป้ายชัดเจน ดู [หลักฐานระยะไข่ Ascaris](docs/atlas/ascaris-stages-evidence.md)
- ระบบบัญชี admin/reviewer/lab/student และ SQLite ที่เปิดด้วย configuration เท่านั้น เก็บภาพ normalized ส่วนตัว ผล AI, quality, reviewer, revision และ audit trail เจ้าของเห็นรายการตนเอง สมัครบัญชีทั่วไปได้เอง ผู้ดูแลอนุมัติผู้เชี่ยวชาญซึ่งต้องยืนยันรหัสผ่านซ้ำก่อนเปิดภาพผู้อื่น/ตรวจทาน ไม่มีบัญชีหรือรหัสผ่านเริ่มต้น
- ตรวจคุณภาพภาพก่อน inference ด้วย heuristic ปรับเกณฑ์ได้ แสดงคำเตือนและต้องยืนยันเหตุผลตามนโยบาย แยกผล AI ที่รอตรวจจากผลยืนยัน และไม่ตีความ confidence เป็นโอกาสติดเชื้อ
- ผู้เชี่ยวชาญยืนยัน แก้ชนิด/กรอบ ทำเครื่องหมาย false positive/ไม่แน่ใจ/ขอตรวจเพิ่ม และเพิ่มกรอบตกหล่น เก็บคำทำนายเดิมและประวัติการแก้ไข ไม่เปลี่ยน weights อัตโนมัติ
- ประวัติรายวันตามเวลาไทยเฉพาะเจ้าของ แยกภาพรอผู้เชี่ยวชาญไว้ในคลังส่งต่อ ผลยืนยันแล้วกลับวันเดิมพร้อมคำตอบ ค้นหา/กรอง/แบ่งหน้าได้ มี PDF ภาษาไทยและ CSV ตามสิทธิ์ Dashboard จากข้อมูล SQL จริง และ feedback เชื่อมรายการตรวจ EPG ยังไม่เปิด
- นำเมนูห้องเรียนพยาธิและส่วนข้อค้นพบสำคัญจากข้อมูลรายปีออกแล้ว โดยคง Atlas/ภาพจริงและกราฟข้อมูลรายปี
- เมื่อยังไม่ตั้งฐานข้อมูล API เดิมทำงานแบบชั่วคราว ไม่เก็บภาพลงดิสก์ ผลบนหน้าเว็บหายเมื่อรีเฟรชหรือปิดหน้า
- โหมดสาธิตแยกชัดเจนว่าเป็นภาพวาดและข้อมูลจำลอง ไม่ใช่ผลตรวจจาก AI

## สถานะโมเดลและ dataset

รายการแหล่งข้อมูลสำหรับฝึกโมเดลตามขอบเขต 11 กลุ่ม สิทธิ์ใช้ และแผนทดสอบกับภาพจริงอยู่ใน [รายงานคัดเลือก dataset](docs/datasets/README.th.md) และ [ทะเบียนแหล่งข้อมูล CSV](docs/datasets/dataset_catalog.csv) ปรับเมื่อ 19 ตุลาคม 2026 โดยเพิ่ม MIF, ตืดแคระ, ตืดหนู, Echinostoma spp. และ Fasciolopsis buski จากขอบเขตเดิม 6 กลุ่มที่มี OV และพัก Schistosoma ทั้งสามชนิดไว้; เป็นการจัดลำดับงานของโครงการ ไม่ใช่ข้อสรุปว่าไม่มี Schistosoma ในไทย

Chula-ParasiteEgg-11 มีชื่อคลาสที่เป็น candidate 9/11 กลุ่มตามขอบเขตไข่เดิม รวม H. nana, H. diminuta และ F. buski แต่ยังไม่พบคลาส MIF หรือ Echinostoma ใน configuration ที่ตรวจ คำว่า 11 ของชื่อ dataset จึงไม่ได้หมายถึงทุกกลุ่มใน Atlas ปัจจุบัน LIDS–UNICAMP เสริมได้ 7/11 กลุ่มในขอบเขตเดิม รวมภาพเป้าหมาย 1,646 ภาพ โดยยังต้องยืนยันสิทธิ์และ provenance ก่อนฝึก Strongyloides ที่เพิ่มใน Atlas ยังไม่ได้เพิ่มข้อมูลฝึกหรือคลาสของโมเดลโดยอัตโนมัติ

ชื่อ OV ต้นทางคือ `Opisthorchis viverrine` ต้องตรวจ annotation และให้ผู้เชี่ยวชาญยืนยัน mapping เป็น O. viverrini ภาพไข่ OV/MIF/Clonorchis และไข่ Echinostoma/Fasciolopsis/Fasciola อาจคล้ายกัน จึงต้องมีตัวอย่างแยกโรคและ reference standard ที่เหมาะสม หากหลักฐานไม่พอให้รายงานลักษณะไข่ไม่แน่ชัดและยืนยันเพิ่ม ไม่แบ่งชนิดจากขนาดเพียงอย่างเดียว และไม่ map Fasciola (ใบไม้ตับ) เป็น Fasciolopsis (ใบไม้ลำไส้) การพบชื่อคลาสในแหล่งข้อมูลหรือการเพิ่ม Atlas ไม่ได้ยืนยันว่า AI ของแอพตรวจได้แล้ว

เริ่มจากภาพของห้องปฏิบัติการได้ตาม [คู่มือเตรียมภาพ 3 ภาพแรกและแผนฝึกโมเดล](docs/training/TRAIN.th.md) โดยทำกรอบให้ผู้เชี่ยวชาญยืนยันก่อน รอบ 3 ภาพนี้ใช้ทดลองเตรียมข้อมูล ไม่ใช้สรุปความแม่นยำของโมเดลกับภาพใหม่

ใช้ [เครื่องมือตรวจกรอบออฟไลน์](tools/review/README.th.md) เพื่อเลือกภาพจากเครื่อง ตรวจ/แก้กรอบ และส่งออก JSON ได้ ตัวเครื่องมือที่เผยแพร่ไม่มีภาพของผู้ใช้และไม่อัปโหลดภาพผ่านเครือข่าย

แหล่งอ้างอิงที่ผู้ใช้ให้: [Kaggle notebook](https://www.kaggle.com/code/mohaliy2016/ai4ntd-kk2-0-p1-5-sth-schm-v2-notebook)

**ยังไม่มี trained weights ใน repository นี้** ไฟล์ notebook ที่แนบมีขนาดเกินขีดจำกัด 32 MiB ของเครื่องมือ และการอ่าน Kaggle จากเครื่องคลาวด์ถูก network proxy ปฏิเสธในรอบสร้าง จึงยังยืนยันสถาปัตยกรรม รายชื่อคลาส dataset หรือประสิทธิภาพของโมเดลต้นฉบับไม่ได้ Atlas เป็นคลังอ้างอิงแยกจากคลาสของโมเดล

API มี adapter เสริมสำหรับ **Ultralytics YOLO detection `.pt` ที่ฝึกแล้ว** นี่เป็นรูปแบบที่ระบบรองรับ ไม่ใช่ข้อยืนยันว่า notebook ที่ให้มาใช้ YOLO หากต้นฉบับใช้รูปแบบอื่น ต้องเพิ่ม adapter ให้ตรงกับโมเดลก่อน

เชื่อมโมเดลที่ทราบแหล่งที่มาและเชื่อถือได้:

```bash
cd /workspace/helpminths
.venv/bin/python -m pip install -r backend/requirements-model.txt
# วางไฟล์โมเดลจริงใน models/parasite_yolo.pt เพื่อให้ระบบค้นพบอัตโนมัติ
# หากใช้ชื่อหรือตำแหน่งอื่น ให้กำหนดพาธเองก่อนเริ่ม API:
# export HELPMINTHS_MODEL_PATH=/private/models/approved-detection.pt
bash scripts/start.sh
```

แหล่งโมเดลปัจจุบันคือ Google Drive ที่เจ้าของส่งให้สำหรับ `results.zip` ระบบ build จะดาวน์โหลดและเลือกโมเดลจากลิงก์นั้นโดยตรง เครือข่ายพัฒนาที่ใช้วันที่ 6 พฤศจิกายน 2569 บล็อก Drive ก่อนถึงไฟล์ จึงยังไม่ได้ตรวจ checkpoint รุ่นใหม่นี้ในเครื่อง แม้โมเดล `parasite_yolo.pt` ที่ส่งก่อนหน้าจะโหลดและประมวลผลผ่าน API ในการทดสอบแยกได้แล้ว ก็ไม่ใช้แทนหรืออ้างว่าเป็นโมเดลเดียวกับ ZIP ใหม่

ชื่อคลาสดึงจาก `model.names` โดยตรง ไม่มีการเดาชื่อชนิดหรือใช้โมเดล COCO ทั่วไปแทนโมเดลไข่พยาธิ เมื่อไม่มีโมเดล `/api/health` จะตอบ `model_ready: false` และการส่งภาพตรวจจริงจะได้รับ HTTP 503 พร้อมคำอธิบาย ไม่ได้สร้างผลตรวจปลอม

`HELPMINTHS_MODEL_PATH` เป็นพาธไฟล์ในเครื่อง ไม่ใช่รหัสลับ ตั้งค่าผ่าน environment ก่อนเริ่ม API แล้วรีสตาร์ตบริการ ต้องตรวจความเข้ากันได้ของโมเดลและชุดทดสอบจริงก่อนใช้ในงานคัดกรอง ผลจาก AI ไม่ใช่การวินิจฉัยทางคลินิกและต้องให้ผู้เชี่ยวชาญยืนยัน

## การตรวจสอบ

หน้า `/#evaluation` เป็นแบบประเมินที่ผู้ใช้ตอบได้ทันที มี SUS 10 ข้อและช่องข้อเสนอแนะหนึ่งช่อง ไม่ต้องลงทะเบียนผู้ทดสอบ จับเวลา สัมภาษณ์ หรือจัดการโครงงาน หน้าโครงงานและหลักฐานถูกนำออกแล้ว รวมถึงป้าย WORKSPACE/พื้นที่ทำงาน

คำตอบเป็นร่างในหน่วยความจำจนกด **บันทึกคำตอบ** จากนั้นเก็บเฉพาะชุดคำตอบล่าสุดบนเบราว์เซอร์ของอุปกรณ์นั้นใน `helpminths.feedback.v1` ไม่มีการส่งเข้าสู่เซิร์ฟเวอร์ ไม่เก็บภาพหรือผลตรวจ AI สูตร SUS คำนวณจากคำตอบครบทั้ง 10 ข้อเป็นคะแนน 0–100 และไม่ใช่ความแม่นยำโมเดล ผู้ใช้กลับมาแก้ไขแล้วบันทึกใหม่ได้ ข้อมูลประเมินรุ่นเก่าใน `helpminths.evaluation.v1` ไม่ถูกอ่าน ลบ หรือเปลี่ยนโดยแบบฟอร์มใหม่

[รายงานและสไลด์วันที่ 25 ตุลาคม 2569](https://github.com/natchabuu-bit/helpminths/raw/refs/heads/main/docs/project/HelpMinths-report-and-slides-2026-10-25.zip) และ [เอกสารตอบข้อเสนอแนะเดิม](docs/project/ADVISOR-RESPONSE.th.md) เก็บเป็นเอกสารย้อนหลังของรุ่นเดิม รูปแบบเว็บในเอกสารนั้นไม่ใช่รุ่นปัจจุบัน

อัปเดตภาพหน้าจอตัวอย่างจากเว็บที่ build และเปิด production server แล้ว:

```bash
HELPMINTHS_TEST_URL=http://127.0.0.1:8081 node scripts/capture-project.mjs
npm run build
```

คำสั่งจับภาพใช้โหมดสาธิตในหน้าตรวจ/ประวัติและไม่มีคำตอบประเมินตัวอย่าง ภาพ Atlas อ้างเครดิตและ CC BY-NC 4.0 ตามภาพต้นทาง การ build หลังจับภาพจะรวมรูปใหม่ในชุดออฟไลน์

```bash
npm run build
.venv/bin/python -m pytest backend/tests -q
curl --fail http://127.0.0.1:8000/api/health
```

Backend tests ตรวจไฟล์ไม่ถูกต้อง ขนาดภาพ ขนาดไฟล์ EXIF orientation ชื่อคลาสและขอบเขตกรอบ โดยใช้ตัวทดสอบแทน predictor เฉพาะ unit test ไม่ใช่การยืนยันความแม่นยำโมเดลจริง

Browser tests ใช้ Playwright โดยเปิดเว็บและ API ด้วย `bash scripts/start.sh` ไว้ก่อน แล้วรัน `npm run test:e2e` ในอีกเทอร์มินัล ถ้ามี Chromium ที่ `/usr/bin/chromium` จะใช้ได้เลย หรือกำหนด `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`; เครื่องอื่นติดตั้งด้วย `npx playwright install chromium` ก่อน ชุดทดสอบตรวจ workflow จริงกับข้อมูลสาธิต และทดสอบสัญญา API ด้วย response จำลองหนึ่งกรณี โดยไม่อ้างว่าเป็นผลจากโมเดลจริง

ทดสอบออฟไลน์กับ production build โดยเปิดบริการไว้ก่อน:

```bash
npm run build
PORT=8081 bash scripts/start-production.sh
```

จากอีกเทอร์มินัลรัน `HELPMINTHS_TEST_URL=http://127.0.0.1:8081 npm run test:offline` ชุดทดสอบนี้เตรียมแคชขณะออนไลน์ แล้วตัดเครือข่ายในเบราว์เซอร์เพื่อตรวจการเปิดหน้าใหม่และฟีเจอร์ออฟไลน์ ไม่ได้ยืนยันว่าโมเดล AI พร้อมใช้งาน

ดูสัญญา API และรายละเอียดการติดตั้งที่ [backend/README.md](backend/README.md)

ไฟล์ `.env.example` เป็นตัวอย่างเท่านั้น ระบบไม่อ่าน `.env` อัตโนมัติ ต้อง export variables ใน shell หรือกำหนดใน settings ของโฮสต์ ตัวเชื่อม YOLO ปัจจุบันใช้ CPU และการปรับภาพ/NMS ของ Ultralytics ยังไม่มี tiled inference หรือโมเดลในเบราว์เซอร์ รุ่นโมเดลอ้าง SHA-256 ของ checkpoint จริง ต้องทดสอบกับอุปกรณ์และภาพอิสระก่อนอ้างความแม่นยำทางคลินิก

## เทคโนโลยี

React 19 + TypeScript + Vite, Three.js / React Three Fiber, FastAPI + Pillow ฟอนต์ Noto Sans Thai และ Inter ติดตั้งในโปรเจกต์และไม่ต้องเรียกเว็บฟอนต์ภายนอก

แบบจำลอง Atlas เป็นภาพอธิบาย morphology ไม่ใช่ภาพถ่ายหรือโครงสร้างสแกน และไม่ใช้สเกลเทียบกันระหว่างชนิด เนื้อหาอ้างอิงรูปแบบลักษณะทั่วไปจาก CDC DPDx โปรดตรวจเอกสารปฐมภูมิและให้ผู้เชี่ยวชาญทบทวนก่อนใช้สอนหรืออ้างอิงทางคลินิก
