# นำเข้าและอัปเดตข้อมูล Dashboard จาก Excel

Dashboard ใช้ชุดข้อมูลสรุปที่สร้างจาก Excel และบันทึกไว้กับโค้ดใน `backend/data/health-survey-2569.json` เมื่อ deploy เว็บ ข้อมูลชุดนี้จะติดไปกับแอป จึงเปิดใช้ต่อได้หลังรีสตาร์ตหรือ deploy ใหม่โดยไม่ต้องพึ่งไฟล์ในแชทหรือพื้นที่ชั่วคราว

การเชื่อมต่อแบบนี้เป็น **snapshot ของไฟล์ที่นำเข้าครั้งล่าสุด** ไม่ได้เฝ้าดูไฟล์ในเครื่อง ไม่ดึงการเปลี่ยนแปลงจาก Google Sheets อัตโนมัติ และไม่มีการอัปเดตผลตรวจแบบสด การวาง Excel ใหม่ในแชทหรือแก้ไฟล์ในเครื่องอย่างเดียวยังไม่เปลี่ยนตัวเลขบนเว็บไซต์

## เส้นทางข้อมูล

```text
Excel ต้นทางที่เก็บเป็นส่วนตัว
    ↓ ตรวจโครงสร้าง จำนวนหลัก และยอดรวม
ตัวนำเข้า backend.platform.import_survey
    ↓ สรุปรวมตามจังหวัด / อำเภอ / สังกัด / สถานะ / ช่วงร้อยละตรวจพบ
backend/data/health-survey-2569.json ที่บันทึกใน Git
    ↓ deploy แอปพร้อมชุดข้อมูล
API สถิติสรุป → Dashboard สาธารณะ
```

ไฟล์สรุปมีมิติกลุ่ม สถิติ แหล่งที่มา และข้อสังเกตคุณภาพข้อมูล ไม่มีชื่อสถานศึกษา ตำบล ข้อมูลรายบุคคล หรือข้อความหมายเหตุต้นฉบับ สถานะคือ `tested` (มีผู้ส่งตรวจ), `zero_tested` (รายงานผู้ส่งตรวจเป็นศูนย์) และ `pending` (ยังไม่มีจำนวนหลัก) จึงกรองข้อมูลได้โดยไม่เปิดเผยแถวรายสถานศึกษา

รุ่นการแปลง `v2` เพิ่มช่วงร้อยละตรวจพบของหน่วยที่มีผู้ส่งตรวจ: 0%, มากกว่า 0 แต่น้อยกว่า 5%, 5 แต่น้อยกว่า 10%, 10 แต่น้อยกว่า 20% และตั้งแต่ 20% ขึ้นไป ช่วงเหล่านี้เป็นการจัดกลุ่มเชิงพรรณนา ไม่ใช่ระดับความเสี่ยงหรือเกณฑ์รักษา หน่วยที่ไม่มีผู้ส่งตรวจหรือยังรอข้อมูลไม่มีช่วงร้อยละ การเลือกช่วงบน Dashboard จะกรองยอดคนและกราฟทุกส่วนจากหน่วยในช่วงนั้นจริง ส่วนแถบจำนวนแต่ละช่วงยังแสดงทุกช่วงภายใต้ตัวกรองพื้นที่/สังกัด/สถานะ เพื่อให้สลับช่วงได้

## 1. เก็บต้นฉบับแยกจากโค้ดสาธารณะ

เก็บ `2569.xlsx` และฉบับแก้ไขไว้ในที่เก็บส่วนตัวที่ผู้รับผิดชอบเข้าถึงได้ สำรองต้นฉบับแยกต่างหาก เพราะ JSON สาธารณะเป็นข้อมูลสรุปและสร้าง Excel รายหน่วยกลับคืนไม่ได้

อย่าเพิ่ม Excel ต้นทางเข้า Git หรือวางในโฟลเดอร์ไฟล์เว็บ เช่น `public/` อย่าส่งข้อมูลระบุตัวบุคคลหรือเพิ่มชื่อสถานศึกษาลงในชุดข้อมูลสาธารณะ ใช้เฉพาะไฟล์สรุปที่ตัวนำเข้าสร้างไว้สำหรับ Dashboard

## 2. สร้างชุดข้อมูลสรุป

เปิด terminal ที่ราก repository ซึ่งมี Python virtual environment และ dependency ของ backend แล้ว แทน `/private/path/2569.xlsx` ด้วยพาธส่วนตัวของไฟล์จริง

```bash
.venv/bin/python -m backend.platform.import_survey /private/path/2569.xlsx --output backend/data/health-survey-2569.json --worksheet เขต2 --year 2569
```

`--worksheet` ต้องตรงกับชื่อแท็บ `--year` เป็น พ.ศ. และต้องปรากฏในชื่อไฟล์ ปีนี้มีที่มาจากชื่อไฟล์ ไม่ใช่การอนุมานวันสำรวจจากวันที่แก้ไข Excel ตัวนำเข้ารองรับแม่แบบหัวตารางสามแถวที่ใช้ในชุดนี้และไฟล์ `.xlsx` ขนาดไม่เกิน 10 MB ไม่ใช่ตัวแปลง Excel ทุกโครงสร้าง

ตัวนำเข้าอ่านค่าที่ Excel บันทึกไว้ ไม่รันสูตรหรือคำสั่งในไฟล์ ตรวจจำนวนหลักว่าเป็นจำนวนเต็มไม่ติดลบและมีความสัมพันธ์ที่เป็นไปได้ เช่น ผู้ตรวจพบไม่เกินผู้ส่งตรวจ หากหัวตารางกำกวม จำนวนหลักขาดบางส่วน หน่วยซ้ำ หรือยอดสรุปไม่ตรงรายละเอียด จะหยุดก่อนแทนที่ชุดข้อมูลเดิม

ช่องว่างทั้งชุดจำนวนหลักจะอยู่ในสถานะรอข้อมูล ไม่แทนเป็นศูนย์ ส่วนช่องชนิดพยาธิที่ว่างหรือขัดกับจำนวนหลักจะถูกเก็บเป็นข้อสังเกตพร้อมแยกยอดตามต้นทางและยอดที่สอดคล้องทางตัวเลข กรณีตัวหารเป็นศูนย์หรือไม่มีข้อมูลจะไม่สร้างร้อยละเป็นศูนย์

ถ้าสูตรใน Excel ยังไม่มีค่าผลลัพธ์ที่บันทึกไว้ ให้เปิดไฟล์ในโปรแกรมตารางคำนวณ คำนวณและบันทึกไฟล์ก่อนนำเข้าใหม่ หากยอดขัดกัน ให้ผู้รับผิดชอบตรวจต้นทางก่อนแก้ไข ไม่ควรเปลี่ยนสูตรหรือเติมศูนย์เพียงเพื่อให้ผ่านการนำเข้า

## 3. ตรวจผลก่อนเผยแพร่

ตรวจข้อความผลนำเข้าและการเปลี่ยนแปลงใน JSON:

```bash
git diff -- backend/data/health-survey-2569.json
git diff --check
.venv/bin/python -m pytest -q backend/tests/test_survey_snapshot.py
```

การตรวจด้วยมือควรครอบคลุมรายการต่อไปนี้:

- มีเฉพาะยอดรวมตามมิติที่อนุญาต ไม่มีรายชื่อสถานศึกษา ตำบล หมายเหตุส่วนตัว หรือข้อมูลรายบุคคล
- จำนวนหน่วยทั้งหมด หน่วยมีผู้ส่งตรวจ หน่วยรายงานศูนย์ และหน่วยรอข้อมูลแยกกันถูกต้อง
- ยอดผู้ส่งตรวจ ผู้ตรวจพบ และนักเรียนที่ทราบตรงกับต้นทางหลังตัดแถวสรุปซ้ำ
- ความครอบคลุมและร้อยละตรวจพบใช้ผลรวมตัวเศษหารผลรวมตัวหาร ไม่เฉลี่ยเปอร์เซ็นต์รายหน่วย และไม่หารด้วยศูนย์
- ผู้ติดพยาธิมากกว่า 1 ชนิดเป็นส่วนหนึ่งของผู้ตรวจพบอยู่แล้ว ไม่บวกเพิ่มในยอดคนรวม
- ข้อสังเกตจำนวนขัดกัน ช่องจำนวนที่ว่าง และสูตรที่ไม่มีตัวหารยังปรากฏ ไม่ถูกลบหรือเติมข้อมูลเอง
- กลุ่มที่ยังรอข้อมูลทั้งหมดแสดงว่าไม่ทราบ ไม่ใช่ผู้ตรวจพบศูนย์คน

ผลอ้างอิงสำหรับต้นฉบับ `2569.xlsx` ที่แนบมา:

| รายการตรวจ | ค่าที่ควรได้ |
| --- | ---: |
| หน่วยทั้งหมด / มีจำนวนหลัก / มีผู้ส่งตรวจ | 174 / 172 / 170 |
| หน่วยรายงานศูนย์ / หน่วยรอข้อมูล | 2 / 2 |
| นักเรียนที่ทราบ / ผู้ส่งตรวจ / ผู้ตรวจพบ | 17,122 / 15,888 / 698 |
| ครอบคลุม / ตรวจพบในผู้ส่งตรวจ | 92.79% / 4.39% |
| ติดพยาธิมากกว่า 1 ชนิด | 17 คน |
| เข็มหมุดตามต้นทาง / หลังแยกค่าขัดกัน / รายการขัดกัน | 7 / 6 / 1 |
| ช่องจำนวนแยกชนิดที่ว่าง | 2 ช่อง |

| หน่วยตามช่วง 0% / >0–<5% / 5–<10% / 10–<20% / ≥20% | 61 / 51 / 32 / 15 / 11 |

ค่าที่เปลี่ยนหลังผู้รับผิดชอบแก้ไขต้นฉบับอาจถูกต้องได้ ให้ตรวจจาก SHA-256 และยอดของฉบับใหม่ ไม่บังคับให้ทุกฉบับเท่ากับตัวเลขเดิม อ่านรายละเอียดและข้อจำกัดใน [รายงานวิเคราะห์ชุดข้อมูล](2569-analysis.th.md)

## 4. บันทึกและ deploy

หลังตรวจข้อมูลแล้ว ให้ผู้ดูแลบันทึก JSON ที่ผ่านการตรวจลง Git และส่ง commit ไปยัง repository ที่ Render ใช้งาน โดยไม่รวม Excel ต้นทาง ตัวอย่างสำหรับชุดข้อมูลปี 2569:

```bash
git add backend/data/health-survey-2569.json
git commit -m "Update public health survey snapshot"
git push
```

การตั้งค่า `render.yaml` ของโครงการใช้ `autoDeploy: false` จึงต้องเปิดหน้า service ของ HelpMinths ใน Render แล้วเลือก **Manual Deploy → Deploy latest commit** รอให้สถานะ deploy สำเร็จ จากนั้นเปิดเมนู Dashboard บนเว็บไซต์ ตรวจแหล่งที่มา ตัวเลขรวม ตัวกรอง และคำเตือนคุณภาพข้อมูล หากเปิดแอปแบบติดตั้งไว้ ให้ปิดทุกหน้าต่างของแอปแล้วเปิดใหม่เพื่อรับเวอร์ชันล่าสุด

หากยังเห็นข้อมูลเดิม ให้ตรวจว่า Render ใช้ repository/branch และ commit ล่าสุดจริง การแก้ไฟล์เฉพาะใน workspace ยังไม่เปลี่ยนเว็บไซต์ที่ deploy อยู่ การเก็บไฟล์ไว้ในดิสก์ runtime ของโฮสต์เพียงอย่างเดียวก็ไม่ใช่การสำรองข้อมูลแบบถาวร

## การติดตามเวอร์ชันและการสำรอง

JSON ระบุชื่อไฟล์ แท็บ ปีที่ใช้แสดง SHA-256 ของต้นทาง เวอร์ชันการแปลง และเวลานำเข้า ทำให้ตรวจได้ว่า Dashboard ใช้ไฟล์ฉบับใด เวลานำเข้าไม่ใช่เวลาสำรวจ การนำเข้าไฟล์และวิธีแปลงเดิมซ้ำจะคงเวลานำเข้าเดิม เพื่อหลีกเลี่ยงการแสดงว่าเป็นข้อมูลใหม่ทั้งที่เนื้อหาไม่เปลี่ยน

โค้ดและ JSON ที่ commit แล้วอยู่ใน repository และนำไปใช้งานต่อได้โดยไม่ผูกกับบัญชี ChatGPT ควรสำรอง repository และ Excel ส่วนตัวแยกกัน หากต้องย้อนกลับ ใช้ commit ก่อนหน้าที่ผ่านการตรวจและ deploy อีกครั้ง สำหรับไฟล์ปีอื่นต้องตรวจโครงสร้างและกำหนดชุดข้อมูล/การตั้งค่าแอปให้รองรับปีนั้นก่อน ไม่ควรเปลี่ยนป้ายปีอย่างเดียว
