# ตรวจหน้าบัญชีผู้เชี่ยวชาญ — เฟส F

สถานะ: ผู้ใช้ยืนยัน “ย่อกล่องสรุปบัญชี” เมื่อ 2026-11-10 แล้ว จึงย่อเฉพาะกล่องนี้ตามที่อนุมัติ

## สิ่งที่ควรคงไว้

- เข้าสู่ระบบผู้เชี่ยวชาญมีเพียงชื่อบัญชีและรหัสผ่าน ใช้ `/expert-signin` ซึ่งยืนยันสิทธิ์ 15 นาทีอยู่แล้ว จึงไม่มีขั้นตอนให้กรอกรหัสผ่านซ้ำทันทีหลังเข้าสู่ระบบ
- ชื่อ-นามสกุล สถานที่ทำงาน สังกัด และเบอร์โทร 10 หลัก เป็นข้อกำหนดการสมัครเดิมของเจ้าของโครงการ ไม่ใช่ข้อมูลซ้ำที่ควรตัดออก
- ช่องยืนยันรหัสผ่านตอนสมัครช่วยป้องกันการพิมพ์ผิด ไม่ได้ปรากฏตอนเข้าสู่ระบบ จึงแนะนำให้เก็บไว้
- การยืนยันรหัสผ่านอีกครั้งเมื่อครบ 15 นาทีหรือเซิร์ฟเวอร์ถอนสิทธิ์เป็นข้อกำหนดด้านการเข้าถึงภาพ ต้องคงไว้
- แท็บผู้ใช้ทั่วไป/ผู้เชี่ยวชาญ กับเข้าสู่ระบบ/สมัครสมาชิกเป็นคนละการตัดสินใจ การรวมเส้นทางเข้าสู่ระบบต้องรักษา `/expert-signin` จึงไม่แนะนำให้ตัดขั้นตอนนี้ทันที
- คำแนะนำรหัสผ่านในหน้าสมัครกับส่วนแก้บัญชีแสดงคนละสถานะการเข้าสู่ระบบ จึงไม่ใช่ข้อความซ้ำพร้อมกัน และช่วยอธิบายช่องที่ผู้ใช้กำลังกรอก

## การย่อกล่องตามคำยืนยัน

ย่อสรุปชื่อ/ชื่อบัญชีในส่วนบนของหน้าบัญชี (`PlatformSettings.tsx` ส่วน `platform-definition-grid`) เพราะชื่อมีในเมนูอวาตาร์และช่องแก้ไขบัญชีด้านล่างแล้ว

- ก่อน: ชื่อ-นามสกุล / บัญชี / สถานะ
- หลังปรับ: บทบาท / สถานะการอนุมัติ
- การย่อกล่องนี้ไม่ลบชื่อ ข้อมูลส่วนตัว ช่องสมัคร หรือช่องแก้ไขบัญชีออกจากระบบ

## ช่องทางเปิดภาพของตนหลังเฟส D

`MyWork.tsx` เปิด `AnalysisHistory` ผ่าน `onOpenAnalysis` ส่วน `AnalysisHistory.tsx` ระบุ `scope: mine` และมีแท็บทั้งหมด/รอตรวจ/เสร็จสิ้นพร้อมสถานะส่งต่อ ผู้เชี่ยวชาญจึงเปิดภาพที่ตนส่งจาก “งานของฉัน” ได้หลังเอาตัวเลือกคลังภาพของตนออกจากคิวผู้เชี่ยวชาญ

## สรุปเฟสที่ทำแล้ว

| เฟส | Branch | ผลการเปลี่ยนแปลง |
| --- | --- | --- |
| A | `expert/phase-a-decisions` | รวมข้อความและการตัดสินใจเป็นชุดเดียว บันทึกแล้วกลับคิว |
| B | `expert/phase-b-object-review` | ปุ่มตัดสินใจ 4 แบบ พับหมายเหตุ/พิกัด เก็บพิกัด AI เดิมเมื่อยืนยัน |
| C | `expert/phase-c-case-layout` | รายละเอียดกระชับ โหมดปิดรายการอ่านอย่างเดียว ลบรายการได้จากประวัติของเจ้าของ |
| D | `expert/phase-d-review-queue` | ลดการ์ดคิวและเอาตัวเลือกคลังซ้ำออก |
| E | `expert/phase-e-preserve-drafts` | เตือนล่วงหน้า 2 นาที ต่ออายุผ่าน modal เก็บร่างและ revision เดิม แก้เมนู/แถบตัดสินใจบนมือถือ |
| E เพิ่มเติม | `expert/phase-e-draft-resume` | เปิดร่างที่บันทึกแล้วต่อได้พร้อมข้อความและเครื่องหมายตรวจทั้งภาพ |
| แจ้งเตือน | `expert/notification-alerts` | กระดิ่งเคลื่อนไหวเมื่อมีงานหรือคำตอบใหม่ รองรับ reduced motion และล้างจำนวนเมื่อล็อก/หมดอายุ |
| F | `expert/phase-f-account-audit` | ย่อกล่องสรุปบัญชีเหลือบทบาทและสถานะตามคำยืนยัน |

ทุกเฟสคง backend, endpoint เดิม, API client, โมเดล, Atlas 3D, action code เก่า, สิทธิ์ภาพ revision guard และข้อความ “ผล AI ต้องได้รับการทบทวนโดยผู้เชี่ยวชาญ” ไว้

## การปรับ test

ปรับชื่อปุ่มและการกลับคิวอัตโนมัติให้ตรงกับ UI ใหม่ ทดสอบขอภาพผ่าน `/analyses/{id}/reviews` แทนฟอร์มตอบแยก และคงการทดสอบ endpoint `/referrals/{id}/response` เดิมสำหรับสิทธิ์/ข้อมูลเก่าไว้

เพิ่มการตรวจปุ่มยืนยันที่ยังใช้ไม่ได้, 4 ตัวเลือกต่อวัตถุ, รายการปิดอ่านอย่างเดียว, การลบจากประวัติของเจ้าของ และร่างที่คงอยู่หลังหมดอายุหรือได้รับ 403 จากเซิร์ฟเวอร์ รวมถึงกรณีแท็บอื่นแก้ไขก่อนซึ่งต้องตอบ 409 โดยไม่เปลี่ยน expected_revision ให้ร่างเงียบ ๆ

ปรับการทดสอบเซสชันหมดอายุให้เปิดประวัติจริง เพราะหน้าแรกไม่ได้โหลด dashboard แล้ว และเพิ่มชุดทดสอบการแจ้งเตือน 6 กรณี

การตรวจมือถือ 375px ผ่าน: เมนูดาวน์โหลดอยู่ในหน้าจอและแตะได้ แถบตัดสินใจเริ่ม sticky หลังเลื่อนถึงฟอร์ม ปุ่มสูง 48px ไม่ทับเมนูล่าง และไม่มีแนวนอนล้น
