# HelpMinths: เริ่มสร้างชุดภาพฝึกจากภาพจริง 3 ภาพ

ปรับปรุง: 23 ตุลาคม 2569 (2026)

ขณะนี้ผู้ใช้มีภาพกล้องจุลทรรศน์ 3 ภาพและผู้ช่วยตรวจยืนยัน แต่ยังไม่ได้ส่งไฟล์ภาพและยังไม่ได้ตีกรอบ จึงเริ่มจากทำข้อมูลอ้างอิงที่ผู้เชี่ยวชาญตรวจแล้วก่อน **ยังไม่มีการฝึกโมเดลหรือผลความแม่นยำจากภาพเหล่านี้** ภาพ 3 ภาพใช้ทดสอบขั้นตอนรับภาพ–ตีกรอบ–ตรวจทานได้ แต่ใช้พิสูจน์ความแม่นยำทางคลินิกไม่ได้

## 1. สิ่งที่ต้องเตรียมสำหรับภาพ 3 ภาพแรก

ส่งไฟล์ต้นฉบับ JPG/PNG โดยคงความละเอียดเดิม ไม่ใช้ภาพหน้าจอ Atlas ภาพ 3D หรือภาพที่วาดกรอบทับจนบังรายละเอียด ตรวจว่ามีสิทธิ์ใช้ภาพเพื่อพัฒนาโมเดล และลบชื่อ เลขผู้ป่วย เลขสิ่งส่งตรวจที่สืบกลับได้ รวมถึงข้อความบนภาพและ metadata ที่ระบุตัวบุคคล ก่อนส่งหรือเก็บบนบริการคลาวด์

เตรียมข้อมูลข้างล่างแยกจากภาพ ใช้รหัสวิจัยที่ไม่ระบุตัวบุคคล ตารางนี้เป็นแบบฟอร์มให้กรอก ไม่ใช่ผลอ่านภาพ:

| ไฟล์ภาพ | ชนิด/กลุ่มที่ผู้เชี่ยวชาญสงสัยหรือยืนยัน | รหัสกลุ่มสิ่งส่งตรวจ/สไลด์ | ข้อมูลเพิ่มเติม |
| --- | --- | --- | --- |
| ภาพที่ 1 | รอระบุ | รอระบุ | วิธีเตรียมตัวอย่าง กำลังขยาย และชนิดกล้อง ถ้าทราบ |
| ภาพที่ 2 | รอระบุ | รอระบุ | ระบุว่าเป็นบริเวณเดียวกับภาพอื่นหรือไม่ |
| ภาพที่ 3 | รอระบุ | รอระบุ | ระบุว่าเป็นสไลด์เดียวกับภาพอื่นหรือไม่ |

ถ้าไม่ทราบรหัสกลุ่ม ให้บอกว่าไม่ทราบ ไม่สร้างรหัสแยกเพื่อให้ดูเหมือนเป็นสิ่งส่งตรวจอิสระ ข้อมูลสเกลที่สอบเทียบแล้ว เช่น µm/pixel มีประโยชน์ต่อการพิจารณาขนาดไข่; กำลังขยายอย่างเดียวใช้แทนสเกลจริงไม่ได้ หากเป็นภาพหลายระยะของวัตถุเดียวกันให้แจ้งไว้ด้วย

ผลที่ควรได้จากรอบนี้คือภาพตัวอย่างพร้อมกรอบที่มีหมายเลขให้ผู้เชี่ยวชาญชี้แก้ไขได้ และข้อสังเกตว่าภาพชัดพอสำหรับจำแนกเพียงใด เมื่อผู้เชี่ยวชาญรับรองแล้วจึงส่งออกไฟล์ YOLO `.txt` รายภาพ พร้อมบัญชี `class_id` เทียบชื่อกลุ่ม **ยังไม่แบ่ง 3 ภาพเป็น train/val/test หรือรายงานคะแนนจากการทายภาพที่ใช้ฝึก**

## 2. วิธีทำกรอบและตรวจยืนยัน

1. เปิดภาพที่แสดงการหมุนตรงกับไฟล์ที่จะใช้ฝึก โดยจัดการ EXIF orientation ก่อนตีกรอบและเก็บไฟล์ที่ใช้อ้างอิงไว้ หากเปลี่ยนขนาดหรือหมุนภายหลังต้องแปลงพิกัดกรอบตามด้วย
2. ตีกรอบสี่เหลี่ยมรอบไข่แต่ละฟองให้ชิดขอบนอกของไข่ ครอบคลุมโครงสร้างที่เป็นส่วนของไข่ ไม่ลากรวมเงา เศษอุจจาระ หรือไข่ข้างเคียงเป็นกรอบเดียว สำหรับ Strongyloides ให้กรอบครอบคลุมตัวอ่อนตามขอบเขตที่เห็นและบันทึกระยะให้ตรง
3. ตรวจทั้งภาพและตีกรอบวัตถุเป้าหมายทุกตัวที่เห็น ไม่ตีเพียงฟองที่เด่นที่สุด บันทึกกรณีซ้อนกัน ขาดขอบภาพ เบลอ หรือมีวัตถุที่ยังระบุไม่ได้ให้ผู้เชี่ยวชาญทบทวน กรอบร่างจากผู้ช่วยหรือ AI ต้องผ่านการรับรองก่อนเป็นข้อมูลจริง
4. ให้ผู้เชี่ยวชาญตรวจชื่อกลุ่ม ขอบกรอบ และวัตถุที่ตกหล่นทีละภาพ บันทึกผู้ตรวจด้วยรหัส วันที่ และสถานะ `draft` / `reviewed` / `uncertain` ความเห็นต่างต้องได้ข้อยุติ หรือพักภาพ/วัตถุนั้นไว้ ไม่บังคับเลือกชนิด
5. ส่งออกทั้งภาพต้นฉบับ annotation และภาพที่แสดงกรอบเพื่อให้ตรวจทานง่าย เก็บฉบับก่อนแก้ไขและบันทึกเหตุผลเมื่อเปลี่ยนชื่อกลุ่ม

ใช้เครื่องมือที่วาดกรอบและส่งออก YOLO detection ได้ เช่น CVAT หรือ Label Studio แบบติดตั้งในเครื่องได้ เลือกสภาพแวดล้อมที่หน่วยงานอนุญาตก่อนอัปโหลดข้อมูลจริงไปยังบริการภายนอก ไม่จำเป็นต้องซื้อบริการติดป้ายเพื่อเริ่ม 3 ภาพนี้

**ภาพที่ยังไม่ได้ตีกรอบไม่ใช่ภาพลบ** ภาพลบต้องได้รับการตรวจทั้งภาพแล้วว่าไม่พบวัตถุเป้าหมาย หากมีไข่ที่อยู่นอกขอบเขตหรือวัตถุที่ผู้ตรวจยังไม่แน่ใจ ต้องบันทึกไว้เพื่อวางนโยบายแยกต่างหาก ไม่ปล่อยให้กลายเป็นพื้นหลังโดยอัตโนมัติ

### รูปแบบ YOLO detection

แต่ละภาพมีไฟล์ `.txt` ชื่อฐานเดียวกัน หนึ่งบรรทัดต่อหนึ่งวัตถุ [1]:

```text
class_id x_center y_center width height
```

`class_id` เป็นจำนวนเต็มเริ่มที่ 0 และตรงกับบัญชีชื่อกลุ่มที่ตกลงกัน ส่วนพิกัด 4 ค่าอยู่ในช่วง 0–1 โดยหารพิกัดแกน x และความกว้างด้วยความกว้างภาพ และหารพิกัดแกน y และความสูงด้วยความสูงภาพ ตัวอย่างเพื่ออธิบายรูปแบบเท่านั้น: ภาพกว้าง 1,000 สูง 800 พิกเซล กรอบจาก `(200, 240)` ถึง `(400, 400)` ของกลุ่ม 0 จะเป็น:

```text
0 0.300000 0.400000 0.200000 0.200000
```

ตัวเลขนี้ไม่ใช่ annotation ของภาพผู้ใช้ ต้องดูภาพจริงก่อนสร้างกรอบ สำหรับโครงการนี้ควรมีไฟล์ label ว่างและสถานะตรวจแล้วอย่างชัดเจนสำหรับภาพลบ เพื่อแยกจากภาพที่ลืมทำ annotation แม้ตัวอ่าน YOLO จะรองรับภาพลบที่ไม่มีไฟล์ label ก็ตาม

## 3. ตกลงชื่อกลุ่มจากหลักฐานที่มองเห็นจริง

เริ่มจากชนิดหรือกลุ่มที่มีในภาพ 3 ภาพนี้ ไม่สร้างคลาสตรวจจับครบทุกชนิดตามรายการ Atlas โดยอัตโนมัติ Atlas ใช้เรียนรู้ ส่วนโมเดลต้องมีตัวอย่างจริงและข้อมูลยืนยันรองรับแต่ละคลาส

- ไข่ OV และ MIF บางกลุ่มมีลักษณะซ้อนทับกัน หากหลักฐานระดับไข่ยังแยกไม่ได้ ให้ใช้กลุ่มที่ผู้เชี่ยวชาญยอมรับหรือพักเป็นกรณียังไม่ยืนยัน ไม่ใช้เพียงชื่อโรคในสิ่งส่งตรวจมาตัดสินไข่แต่ละฟอง
- ไข่ Taenia ใช้ระดับ `Taenia spp.` เมื่อภาพไข่แยกชนิดไม่ได้ ไข่พยาธิใบไม้ที่มีฝาขนาดใหญ่หลายชนิดอาจคล้ายกัน ต้องกำหนดระดับรายงานตามหลักฐานที่มี
- Strongyloides ที่ตรวจอุจจาระโดยทั่วไปเป็นตัวอ่อน ต้องทำข้อมูลตัวอ่อนแยกจากไข่และระบุระยะ ผู้เชี่ยวชาญต้องตรวจลักษณะประกอบ เช่น ช่องปากสั้นและ genital primordium ของตัวอ่อน rhabditiform ไม่ใช้จุดเด่นเดียวแทนการยืนยันทั้งหมด

แยกชื่อดั้งเดิมของแหล่งข้อมูลกับชื่อมาตรฐานที่ตกลงใช้ และเก็บตารางเทียบชื่อพร้อมเหตุผล ดูแหล่งข้อมูลที่ตรวจไว้แล้วใน [ทะเบียนชุดข้อมูล](../datasets/README.th.md) และหลักฐานกับข้อจำกัดใน [EVIDENCE.th.md](EVIDENCE.th.md)

## 4. เมื่อผ่านรอบทดลองแล้ว จึงขยายข้อมูลและแยกชุดประเมิน

จำนวนภาพเพียงอย่างเดียวไม่รับประกันความแม่นยำ ควรนับจำนวนไข่และจำนวนสิ่งส่งตรวจอิสระต่อกลุ่มด้วย เก็บภาพเต็มมุมมองที่มีไข่น้อย/มาก ภาพลบที่ผู้เชี่ยวชาญตรวจแล้ว สิ่งรบกวนที่คล้ายไข่ ตลอดจนความหลากหลายของอุปกรณ์ การเตรียมสไลด์ ความคมชัด และวันเก็บภาพจากการใช้งานจริง ไม่เก็บเฉพาะภาพสวยหรือภาพครอปไข่เดี่ยว

เมื่อมีข้อมูลอิสระเพียงพอ ให้แยกชุดดังนี้ โดยล็อกบัญชีไฟล์ก่อนฝึก:

| ชุด | ใช้ทำอะไร | ข้อกำหนด |
| --- | --- | --- |
| train | เรียนรู้จากภาพและกรอบ | ทำ augmentation เฉพาะชุดนี้ |
| validation | เลือกโมเดล ขนาดภาพ และเกณฑ์ confidence | ไม่เป็นข้อมูลฝึก และไม่ใช้แทน test |
| test | ประเมินรุ่นที่ตรึงโมเดลและค่าต่าง ๆ แล้ว | เก็บแยก ไม่ใช้เลือกโมเดลหรือปรับเกณฑ์ |

ผู้ป่วย/สิ่งส่งตรวจ/สไลด์เดียวกันต้องอยู่ชุดเดียวกันตามความเชื่อมโยงสูงสุดที่ทราบ ภาพครอป ภาพซ้ำ ภาพต่างระยะโฟกัส ภาพหลายบริเวณจากตัวอย่างเดียวกัน และภาพดัดแปลงต้องตามต้นฉบับไปชุดเดียวกัน แยกก่อนสร้างภาพเพิ่ม หากไม่ทราบที่มาพอจะยืนยันความอิสระ ต้องบอกข้อจำกัดนี้; การสุ่มชื่อไฟล์ไม่แก้ปัญหา

อย่ากำหนดอัตราแบ่งจนแต่ละกลุ่มเหลือเพียงตัวอย่างทดสอบรายเดียว เก็บเพิ่มตามกลุ่มที่ขาดและดูผลเมื่อเพิ่มข้อมูลจริง หากนำข้อมูลสาธารณะมารวม ต้องตรวจสิทธิ์ใช้และเผยแพร่โมเดล ความซ้ำกับชุดอื่น ชนิด annotation และระดับการยืนยันก่อน อ่านรายละเอียดได้จากทะเบียนชุดข้อมูล ไม่ใช้ภาพอ้างอิงใน Atlas เป็นชุดทดสอบทางคลินิก

## 5. แผนฝึกเมื่อข้อมูลพร้อม

ระบบปัจจุบันรองรับ Ultralytics YOLO **detection** checkpoint `.pt` ผ่าน `backend/requirements-model.txt` (`ultralytics>=8.3,<9`) แนวเริ่มทดลองที่เข้ากันได้คือ `yolov8s.pt` จากผู้พัฒนา Ultralytics แล้วฝึกต่อด้วยข้อมูลของโครงการ [2–3] น้ำหนักเริ่มต้นฝึกจาก COCO ไม่ได้รู้จักไข่พยาธิโดยตรง และยังไม่มีหลักฐานว่าเป็นสถาปัตยกรรมที่ดีที่สุดสำหรับ HelpMinths

เมื่อมี annotation ที่ตรวจแล้วและแบ่งชุดถูกต้อง จึงเตรียม Colab/Kaggle GPU หรือเครื่อง GPU ของหน่วยงาน ใช้เวอร์ชันไลบรารีที่ทดสอบเข้ากับ runtime จริงและบันทึกเลขเวอร์ชันทั้งหมด ตรวจเงื่อนไขของไลบรารีและน้ำหนักเริ่มต้นแยกจากสิทธิ์ภาพก่อนนำโมเดลขึ้นบริการ ใช้ภาพที่มีสิทธิ์และไม่มีข้อมูลระบุตัวบุคคล เก็บชุดภาพไว้นอก repository Git ที่เผยแพร่ ไม่วางลิงก์ข้อมูลหรือข้อมูลรับรองส่วนตัวใน notebook

แนวทดลองเริ่มต้นที่ต้องทดสอบบน validation:

- ลองความละเอียด `imgsz=1024` เพื่อรักษารายละเอียดวัตถุเล็ก และพิจารณา 1280 เมื่อหน่วยความจำและผล validation รองรับ วัดขนาดไข่หลังย่อจริง การเพิ่ม resolution ไม่ช่วยถ้าต้นฉบับเบลอ
- เริ่ม batch ตาม GPU ที่มี; Ultralytics รองรับ `batch=-1` สำหรับ AutoBatch [3] หากหน่วยความจำไม่พอให้ลด batch ก่อน อย่าสัญญาว่า GPU ฟรีจะใช้ได้เสมอ
- เริ่ม augmentation อย่างระมัดระวังและตรวจภาพที่แปลงแล้วกับผู้เชี่ยวชาญ การหมุน/กลับภาพอาจสมเหตุสมผลกับไข่ที่วางตัวได้หลายทิศ แต่การยืดรูป เปลี่ยนสีรุนแรง หรือทำ mosaic จนไข่เล็กมากอาจทำลายลักษณะที่ใช้จำแนก ห้ามใช้ augmentation สร้างภาพทดสอบเพิ่มแล้วนับเป็นผู้ป่วยใหม่
- เลือก checkpoint และเกณฑ์ confidence จาก validation ตรวจข้อผิดพลาดรายกลุ่มก่อนตรึงค่า จากนั้นจึงประเมิน test เพื่อรายงานผล หากนำผล test ไปปรับโมเดล ต้องถือว่าชุดนั้นถูกใช้พัฒนาแล้วและจัดชุดทดสอบอิสระใหม่

ยังไม่จัด notebook ฝึกจากภาพ 3 ภาพนี้ เพราะยังไม่มีภาพจริง กรอบ ชื่อกลุ่ม และชุดประเมินที่ใช้ได้ เมื่อข้อมูลพร้อมจึงเพิ่มขั้นตอนที่รันได้กับโครงสร้างไฟล์จริง ไม่ใส่ผลทดลองจำลองหรือคะแนนที่ยังไม่ได้วัด

## 6. สิ่งที่ต้องตรวจให้ครบก่อนเชื่อมโมเดลกับเว็บ

ส่งมอบ `best.pt` พร้อมบัญชีชื่อกลุ่ม/ลำดับ class ID เวอร์ชัน Ultralytics/PyTorch ขนาดภาพที่ประเมิน การจัดการสี/การหมุน เกณฑ์ confidence และ NMS ตลอดจนทะเบียนชุดข้อมูลและรายงาน validation/test เก็บ checksum ของ checkpoint เพื่อระบุรุ่นที่ใช้งานจริง [4] ไฟล์ `.pth` จาก framework อื่นหรือโมเดล classification ใช้แทน `.pt` detection นี้ไม่ได้ทันที

**ต้องระบุขนาดภาพให้ตรงกันระหว่างฝึก ประเมิน และระบบใช้งาน** ตอนตรวจโค้ดรอบนี้ `backend/model.py` เรียก `predict()` โดยไม่ระบุ `imgsz` ขณะที่ค่าปริยายใน Ultralytics v8.3.0 คือ 640 [5] จึงต้องตั้งค่าการอนุมานและทดสอบร่วมกับเว็บก่อนนำโมเดลที่ประเมินที่ 1024/1280 ไปใช้จริง การฝึกที่ความละเอียดสูงอย่างเดียวไม่ยืนยันผลเมื่อเว็บย่อภาพด้วยค่าอื่น

รายงาน mAP50 และ mAP50–95 พร้อม precision/recall รายกลุ่มที่เกณฑ์ซึ่งตรึงไว้ จำนวนกรอบ จำนวนภาพ และจำนวนสิ่งส่งตรวจอิสระ ตรวจการพลาดไข่และการตีกรอบสิ่งรบกวน รวมถึง false positives ต่อภาพลบ ผู้เชี่ยวชาญควรทบทวนผลลัพธ์บนภาพจริง วัดเวลาและหน่วยความจำบนเซิร์ฟเวอร์ CPU ที่ใช้งาน ไม่ใช้เวลา GPU แทนเวลาเว็บ

ถ้าจะรายงานความไวระดับสิ่งส่งตรวจ ต้องมีสิ่งส่งตรวจบวก/ลบอิสระและเกณฑ์อ้างอิงที่เหมาะสม รวมผลทุกภาพตาม protocol การเก็บจริง คะแนน detection ต่อไข่ไม่ใช่ความไวในการวินิจฉัยผู้ป่วย ค่า confidence ไม่ใช่โอกาสที่ผู้ป่วยติดเชื้อ และภาพเดียวที่ไม่พบไข่ไม่ตัดโรคออก
