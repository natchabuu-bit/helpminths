# HelpMinths: แหล่งข้อมูลไข่พยาธิสำหรับพัฒนาโมเดลตรวจจับ

วันที่ตรวจสอบ: 19 ตุลาคม 2569 (2026) • วัตถุประสงค์: คัดเลือกข้อมูลวิจัยเพื่อฝึกโมเดลที่แสดงกรอบและจำแนกไข่พยาธิบนภาพกล้องจุลทรรศน์จริง

## ข้อเสนอที่ใช้ตัดสินใจได้

**ควรเริ่มจาก Chula-ParasiteEgg-11 สำหรับการตรวจจับ 5 กลุ่มในแอพ เสริมข้อมูลจากบราซิลสำหรับความหลากหลายและ Schistosoma mansoni แล้วสร้างชุดทดสอบจากห้องปฏิบัติการและโทรศัพท์ที่จะใช้จริงในไทย** ขณะนี้ยังไม่มีชุดข้อมูลที่ตรวจสอบในรอบนี้ซึ่งยืนยันว่าพร้อมใช้งานครบทั้ง 8 กลุ่ม พร้อมสิทธิ์และข้อมูลผู้ป่วย/สไลด์ที่เพียงพอสำหรับอ้างความแม่นยำทางคลินิก

แหล่งด้านล่างมีหลักฐานจากสถาบันหรือผู้เขียนงานวิจัยโดยตรง แต่ **ยังไม่มีแหล่งใดที่ตรวจสิทธิ์ การเข้าถึง และ provenance ครบสำหรับนำเข้าโครงการทันที** จึงจัดสถานะทั้งหมดเป็น `rights/provenance_pending` ในทะเบียนแนบ OpenUrine มีข้อกำหนดวิจัยและไม่ใช้เชิงพาณิชย์ที่อ่านได้ แต่ยังต้องขออนุมัติและตรวจขอบเขตการใช้โมเดล การมี GitHub สาธารณะหรือ license ของโค้ดไม่ได้ยืนยันสิทธิ์ภาพ

รายการ 8 กลุ่มอ้างอิงจาก Atlas ในซอร์สแอพ: Ascaris lumbricoides, Trichuris trichiura, Hookworm, Schistosoma mansoni, S. haematobium, S. japonicum, Taenia spp. และ Enterobius vermicularis การอยู่ใน Atlas ไม่ได้หมายความว่ามีโมเดลที่ตรวจชนิดนั้นได้แล้ว และการรวบรวมข้อมูลครั้งนี้ยังไม่ได้ฝึกหรือทดสอบโมเดลใหม่

## 1. ชุดข้อมูลที่ควรขอใช้ตามลำดับ

### 1.1 Chula-ParasiteEgg-11 / IEEE ICIP 2022 — ตัวเลือกหลักสำหรับกรอบตรวจจับ

- ต้นทางข้อมูล: [IEEE DataPort](https://ieee-dataport.org/competitions/parasitic-egg-detection-and-classification-microscopic-images) และ [เว็บไซต์การแข่งขัน](https://icip2022challenge.piclab.ai/)
- หลักฐานที่อ่านได้: [โค้ดทีม Biomedical and Data Lab มหาวิทยาลัยมหิดล](https://github.com/biodatlab/icip-challenge-2022), [configuration ที่ระบุคลาสและกรอบ COCO](https://github.com/biodatlab/icip-challenge-2022/blob/main/configs/tood_r101_dconv_10epoch.py), [UCLM-VISILAB](https://github.com/UCLM-VISILAB/Segmented-Chula-ParasiteEgg-11-CODE) และ [Tomas Bata University A.I. Lab](https://github.com/TBU-AILab/ICIP2022-ParEggChallenge)
- รองรับ **5/8 กลุ่ม**: Ascaris, Trichuris, Hookworm egg, Taenia spp. egg และ Enterobius; ไม่พบ Schistosoma ทั้งสามชนิดใน configuration 11 คลาสที่ตรวจ
- Annotation: configuration ใช้ `CocoDataset`, `with_bbox=True` และประเมิน `bbox` จึงมีหลักฐานการใช้เป็น object detection จริง แต่ยังไม่ได้ตรวจไฟล์ JSON ต้นฉบับ
- จำนวน: README ของ UCLM ระบุ **11,000 ภาพ train/validation และ 2,200 ภาพ test** ส่วน README ทีมมหิดลกล่าวถึงประมาณ **1,650 ภาพ test** อาจเป็นคนละ release/subset ต้องตรวจ manifest ก่อนรวมจำนวน ตัวเลขนี้เป็นจำนวนภาพ ไม่ใช่ผู้ป่วย ไข่ หรือสไลด์
- สิ่งที่ต้องขอเพิ่ม: license/ข้อตกลงต้นทาง, version, รายการภาพและกรอบต่อคลาส, จำนวนผู้ป่วย/สไลด์, วิธีเตรียม, อุปกรณ์ และขั้นตอนผู้เชี่ยวชาญยืนยัน label

ชุดนี้เหมาะเริ่ม detector หลายชนิดมากกว่าการเริ่มจากภาพไข่ที่ครอปแล้ว แต่ยังต้องตรวจความครบของกรอบในภาพเต็มและภาพ negative ของ release จริง เว็บไซต์ต้นทางถูก proxy ของสภาพแวดล้อมนี้ปฏิเสธก่อนเชื่อมต่อสำเร็จ จึงยังไม่ยืนยันเงื่อนไขดาวน์โหลดหรือการต้องมีบัญชี ไม่ได้หมายความว่าผู้ใช้จะเปิดจากเครื่องตนเองไม่ได้

**ข้อควรระวัง:** README ทีมมหิดลใช้ pseudo-label จาก test เพื่อฝึกต่อ ผลแข่งขัน/weights ดังกล่าวจึงไม่ใช่หลักฐานทดสอบภายนอกที่โมเดลไม่เคยเห็นข้อมูล และ weights `.pth` ของ MMDetection ไม่ใช่ YOLO `.pt` ที่เสียบกับ adapter ของแอพได้ทันที

### 1.2 LIDS–UNICAMP Intestinal Parasites Datasets — เสริม morphology และสิ่งรบกวน

- ต้นทางสถาบัน: [Laboratory of Image Data Science, UNICAMP ประเทศบราซิล](https://github.com/LIDS-UNICAMP/intestinal-parasites-datasets)
- ไฟล์: [helminth-eggs](https://github.com/LIDS-UNICAMP/intestinal-parasites-datasets/tree/main/helminth-eggs), [manifest split1](https://raw.githubusercontent.com/LIDS-UNICAMP/intestinal-parasites-datasets/main/helminth-eggs/splits/split1.json)
- จำนวนที่ตรวจจาก README และชื่อไฟล์ไม่ซ้ำใน manifest: **5,112 ภาพ = ภาพกลุ่มพยาธิ 1,768 + ภาพสิ่งรบกวน 3,344** ไม่ใช่ไข่พยาธิ 5,112 ฟอง
- มี labels ตามภาพและ segmentation masks จำนวนรายกลุ่มในตารางด้านล่างยืนยันจาก manifest; ยังไม่ใช่ COCO/YOLO กรอบภาพสนามจริง
- ตรวจตัวอย่าง PNG แรก 10 ภาพได้ขนาด 200 × 200 พิกเซล และตัวอย่างที่ดูเป็นวัตถุที่แยกพื้นหลังเป็นสีดำแล้ว จึงเหมาะเสริมการจำแนกรูปร่าง/วัตถุและ hard negatives มากกว่าจะใช้แทนภาพกล้องจุลทรรศน์เต็มภาพ ไม่ได้ยืนยันว่าทุกภาพใน archive มีรูปแบบเดียวกัน

| คลาสต้นทาง | จำนวนภาพ | การใช้งานสำหรับแอพ |
|---|---:|---|
| Ascaris lumbricoides | 337 | ตรงกลุ่มในแอพ |
| Trichuris trichiura | 375 | ตรงกลุ่มในแอพ |
| Ancylostoma | 148 | รวมรายงานเป็น Hookworm; ยังไม่ครอบคลุม hookworm ทุกชนิด |
| Enterobius vermicularis | 122 | ตรงกลุ่ม แต่ยังต้องมีภาพเทปใสจากงานจริง |
| Schistosoma mansoni | 122 | เสริมชนิดที่ Chula ไม่มี |
| Taenia spp. | 236 | คงการรายงานระดับ spp. |
| Hymenolepis nana / H. diminuta | 348 / 80 | นอก 8 กลุ่มปัจจุบัน; ควรเป็นคลาสนอกขอบเขตที่ระบุชัด |
| Impurities | 3,344 | สิ่งรบกวนแบบ crop; ต้องเสริม negatives แบบภาพเต็ม |

รวมตรงกลุ่มแอพ **6/8 กลุ่ม รวม 1,340 ภาพ** ไม่พบ S. haematobium หรือ S. japonicum แหล่งสถาบันและไฟล์เข้าถึงได้ แต่ยังไม่พบ license ของ dataset และ metadata ไม่ยืนยันผู้ป่วย/สไลด์ อุปกรณ์ วิธีเตรียม และขั้นตอนตัดสิน label ระหว่างผู้เชี่ยวชาญ Split ที่มีเป็นระดับภาพ ไม่ได้ยืนยันการแยกผู้ป่วย การสร้างกรอบจาก mask รอบวัตถุที่ครอปไม่ทำให้ชุดนี้เป็นการตรวจไข่หลายฟองบนภาพเต็มโดยอัตโนมัติ

### 1.3 S. mansoni แบบ Kato–Katz จากกลุ่ม UFMG — ชุดงานวิจัยต้นทางขนาดเล็ก

- ผู้เขียนและโค้ด: [detection-eggs-schisto](https://github.com/brunoalbertobambui/detection-eggs-schisto)
- ต้นทางข้อมูลที่ README ผู้เขียนเชื่อมโดยตรง: [Mendeley Data version 2](https://data.mendeley.com/datasets/5ckgmp4zzj/2)
- งานต้นฉบับ: [Automated Diagnosis of Schistosomiasis… Kato-Katz Technique](https://doi.org/10.1007/s00521-022-06924-z)
- README ยืนยัน **66 ภาพจริง** ของ S. mansoni เตรียมด้วย Kato–Katz งานใช้ Faster R-CNN ตรวจกรอบไข่; ไม่ได้ยืนยันจำนวนผู้ป่วย สไลด์ ไข่ทั้งหมด หรือรูปแบบ annotation ในไฟล์ฝากข้อมูล
- ผู้เขียนมีสังกัด UFMG ประเทศบราซิล รวมภาควิชาปรสิตวิทยา แต่ยังไม่ยืนยันสถานที่เก็บสิ่งส่งตรวจจาก README
- เหมาะเสริมสภาพภาพอุจจาระและเป็นชุดทดลองต่างแหล่งหลังตรวจการซ้ำ/สิทธิ์ **ขนาดเล็กเกินกว่าจะเป็นฐานฝึกเพียงชุดเดียว** ตัวเลข AP ในงานเป็นผลเฉพาะการทดลองของผู้เขียน ไม่ใช่ความแม่นยำของ HelpMinths

Mendeley และบทความต้นทางถูกจำกัดการเข้าถึงจากเครือข่ายนี้ จึงยังไม่ได้อ่าน license หรือไฟล์ annotation จริง ไม่มีการสรุปว่าเป็น YOLO/COCO พร้อมใช้

### 1.4 S. mansoni จำนวน 1,219 คู่ภาพ–mask จาก LIDS-Datasets

- ต้นทางผู้วิจัย: [schistossoma-eggs](https://github.com/LIDS-Datasets/schistossoma-eggs) (ชื่อ repository สะกดตามต้นทาง)
- มี **1,219 ภาพและ 1,219 segmentation masks** จากจำนวนรายการในโฟลเดอร์ `orig` และ `label`; จำนวนใน `orig` มีโฟลเดอร์ checkpoints เพิ่มอีก 1 รายการ จึงไม่นับเป็น 1,220 ภาพ
- README ระบุภาพอุจจาระ S. mansoni และอ้างงาน *Adaptive Decoders for FLIM-based Salient Object Detection Networks*, SIBGRAPI 2024
- แปลง mask เป็นกรอบได้เมื่อทบทวนว่า connected components ตรงกับไข่แต่ละฟองจริง; ภาพไข่ชิดกันหรือขาดส่วนต้องให้ผู้เชี่ยวชาญตรวจ
- ยังไม่พบ license และข้อมูลผู้ป่วย/สไลด์ อุปกรณ์ การเตรียม หรือการอ่านยืนยัน; **ยังไม่ยืนยันการซ้ำกับ LIDS intestinal subset หรือชุด 66 ภาพ** จึงห้ามนำยอดมาบวกเป็นจำนวนผู้ป่วยอิสระ

[AutoFLIM](https://github.com/LIDS-UNICAMP/AutoFLIM) กล่าวถึง benchmark 1,219 ภาพเช่นกัน ให้ถือเป็นหลักฐานประกอบ/แหล่งอาจซ้ำ ไม่ใช่เพิ่มอีก 1,219 ภาพ ชุด few-shot splits ใน repository ไม่ใช่ตัวแทนการแบ่งทดสอบทางคลินิก

## 2. ช่องว่างสำคัญของ Schistosoma อีกสองชนิด

### S. haematobium: OpenUrine เป็นแหล่งขอเข้าถึงที่ควรตรวจต่อ

[OpenUrine](https://github.com/alikarimi120/OpenUrine) เป็น repository ของผู้เขียนที่มีสังกัด University of Tehran และ Shahid Beheshti University of Medical Sciences ประเทศอิหร่าน README ระบุ **6,430 ภาพตะกอนปัสสาวะ: 790 ภาพมี labels รวม 31,285 bounding boxes ใน 39 กลุ่ม และอีก 5,640 ภาพไม่มี labels** รายการกลุ่มมี S. haematobium และ Enterobius vermicularis แต่ **ยังไม่ทราบจำนวนภาพ/กรอบของพยาธิแต่ละชนิดและระยะที่ annotate** ห้ามเรียก 31,285 boxes ว่าไข่พยาธิทั้งหมด

ผู้เขียนระบุการเก็บจากหลายห้องปฏิบัติการ หลายกล้องจุลทรรศน์/กล้องโทรศัพท์ อ่าน annotation อิสระโดยผู้เชี่ยวชาญชีวเคมีคลินิกสองคน และแบ่งตามผู้ป่วย เหล่านี้เป็นข้อความใน README ที่ยังไม่ได้ตรวจเทียบไฟล์หรือ data dictionary; ยังไม่ทราบวิธีตัดสินความเห็นต่างและจำนวนผู้ป่วยจริง การมี Enterobius ในปัสสาวะไม่ได้ยืนยันผลบนเทปใส

เข้าถึงผ่าน [แบบฟอร์มขอข้อมูล](https://forms.gle/JKgV63B6hdr5XjD29) โดยกำหนด **วิจัยเชิงวิชาการ/ไม่ใช้เชิงพาณิชย์ ห้ามส่งต่อข้อมูลโดยไม่มีอนุญาต และต้องอ้างอิง** ยังไม่มีการยื่นขอแทนผู้ใช้ ต้องยืนยันการนำโมเดลที่ฝึกไป deploy บน HelpMinths ด้วย Repository ที่ตรวจมีเพียง README จึงยังไม่ยืนยันโค้ด/weights/ตัวอย่างภาพที่ข้อความกล่าวถึง งาน Scientific Reports 2025 ที่ผู้เขียนอ้างยังเปิด publisher ตรวจอิสระไม่ได้ ไม่สร้าง DOI ขึ้นเอง

**บทบาทที่แนะนำ:** แหล่ง candidate สำหรับ S. haematobium และสิ่งรบกวนในปัสสาวะ เมื่อได้อนุญาต ตรวจ label รายชนิดและคุณภาพจริงแล้ว การพบชื่อใน README ยังไม่ยืนยันว่ามีไข่เพียงพอสำหรับฝึก

### S. haematobium: Schistoscope เป็นแหล่งงานวิจัย แต่ยังไม่ยืนยันข้อมูลเปิด

Schistoscope เป็นงานจากเครือข่าย Delft/Leiden และผู้ร่วมวิจัยในแอฟริกา มี [งานตีพิมพ์ปี 2022](https://doi.org/10.3390/mi13050643), [author repository](https://github.com/delftopenhardware/Schistoscope) และ [ข้อความบทคัดย่อในเว็บไซต์ผู้เขียน](https://github.com/delftopenhardware/SchistoscopeDocs/blob/main/classic/src/components/HomepageFeatures/index.tsx) ซึ่งกล่าวถึง **มากกว่า 5,000 ภาพจากปัสสาวะทั้งแบบเติมไข่และสิ่งส่งตรวจทางคลินิก** ไม่ใช่ผู้ป่วยติดเชื้อธรรมชาติ 5,000 ราย

อย่างไรก็ตาม [เอกสารข้อมูลของผู้เขียน](https://github.com/delftopenhardware/SchistoscopeDocs/blob/main/classic/docs/docs_data/intro.md) ระบุชัดว่า “Currently the dataset used to train the algorithm is not available…” จึงเป็น **แหล่งติดตาม/ขอความร่วมมือ ยังไม่ยืนยันว่าเป็น dataset เปิดที่ดาวน์โหลดฝึกได้** หน้านี้อาจเก่ากว่า release ใหม่ ต้องตรวจสถานะล่าสุดกับเจ้าของ ยังไม่มีการติดต่อแทนผู้ใช้

ลิงก์ Zenodo `10211154` ในเอกสารซอฟต์แวร์เป็น image ระบบปฏิบัติการสำหรับ Raspberry Pi ไม่ใช่ชุดภาพไข่พยาธิ ต้องแยกออกจากทะเบียนภาพฝึก

### S. japonicum: ยังไม่ยืนยันต้นทางชุดตรวจไข่ที่ดาวน์โหลดได้

การค้นครั้งนี้ยังไม่ยืนยันชุดภาพไข่ S. japonicum ที่มี annotation สำหรับ detection พร้อมต้นทางและสิทธิ์ที่ตรวจได้ ไม่ได้แปลว่าไม่มีข้อมูลอยู่ที่ใดในโลก ควรค้นต่อผ่านผู้เขียนงาน/สถาบันที่ทำ microscopy ของชนิดนี้ หรือสร้างความร่วมมือกับห้องปฏิบัติการที่มีสิ่งส่งตรวจจริง ข้อมูลจีโนม ภาพอัลตราซาวนด์ตับ และภาพอวัยวะไม่ใช้แทนข้อมูลไข่กล้องจุลทรรศน์

## 4. แหล่งที่ไม่ควรตีความผิด

- [Kaggle notebook ที่ผู้ใช้ส่ง](https://www.kaggle.com/code/mohaliy2016/ai4ntd-kk2-0-p1-5-sth-schm-v2-notebook) เป็นหน้าโค้ด ไม่ใช่หลักฐานชุดข้อมูลต้นฉบับในตัวเอง รอบนี้ยังเปิด Input/Data panel ไม่ได้ ต้องตามไปยัง Data Card ของทุก dataset ที่ notebook ใช้ จึงจะยืนยันผู้สร้าง รุ่น คลาส จำนวน label และสิทธิ์ได้ ไม่สรุปว่าครบ 8 กลุ่มจากชื่อ notebook
- Segmented Chula ของ UCLM ใช้ภาพ Chula เดิมและสร้าง masks ด้วย SAM ไม่ใช่ข้อมูลผู้ป่วยเพิ่มหรือ masks ที่ผู้เชี่ยวชาญวาดยืนยันทั้งหมด ห้ามใช้เป็น external test เมื่อฝึกด้วย Chula
- Kaggle/Roboflow/GitHub mirror อาจเป็นภาพเดียวกัน; อย่านับเป็นข้อมูลจากหลายประเทศเพียงเพราะมีหลายเว็บไซต์ ต้องตรวจ collection site จริง
- CDC DPDx ใช้เป็นแหล่งตรวจความรู้ morphology ได้ แต่ไม่ควร scrape เป็น bulk training corpus โดยยังไม่ตรวจเครดิตและเงื่อนไขของแต่ละภาพ ภาพ 3D Atlas ในแอพเป็นสื่อเรียนรู้ ไม่ใช่ clinical ground truth
- ข้อมูลไข่พยาธิสัตว์หรือโปรโตซัว/Babesia/Toxoplasma ไม่แทน 8 กลุ่มไข่มนุษย์ในแอพ อาจเป็นข้อมูลเสริมที่ระบุบทบาทชัดเจนเมื่อมีเหตุผลและสิทธิ์รองรับ

## 5. จาก dataset ไปสู่ความแม่นยำที่ตรวจสอบได้

1. **เคลียร์ต้นทางและสิทธิ์ก่อนนำเข้า:** บันทึกรุ่น, checksum, สิทธิ์ภาพ/annotation/weights, patient–specimen–slide IDs, วิธีเตรียมและอุปกรณ์ ตรวจกรอบตกหล่น ไฟล์เสีย class mapping และ duplicates ข้ามทุกแหล่ง
2. **เพิ่มภาพเต็มจากงานจริง:** เก็บภาพจากกล้องจุลทรรศน์และโทรศัพท์เป้าหมาย มีทั้งหลายฟอง การติดเชื้อร่วม ภาพไม่พบไข่ และฟองอากาศ เศษพืช เซลล์/วัสดุในเทป รวมถึงไข่ชนิดนอกขอบเขต ให้ผู้เชี่ยวชาญอย่างน้อยสองคนอ่าน subset ที่กำหนดอย่างอิสระและมีผู้ตัดสินความเห็นต่าง
3. **แบ่งกลุ่มก่อน crop/augment:** แยก train/validation/test ตามผู้ป่วยหรือสไลด์ รวมภาพหลาย field/focus ของตัวอย่างเดียวไว้ฝั่งเดียวกัน แยกชุดทดสอบภายนอกจากห้องปฏิบัติการ ช่วงเวลา หรืออุปกรณ์ใหม่ และไม่ใช้ชุดนี้ปรับ threshold หรือสร้าง pseudo-label ฝึกต่อ
4. **ฝึก baseline detector:** เช่น YOLO/Faster R-CNN ที่รับภาพเต็ม/patch เมื่อไข่เล็ก และตรวจการรวมกรอบซ้ำ; แยกวิเคราะห์ stool, urine และ tape เพราะพื้นหลังและ SOP ต่างกัน ไม่ให้โมเดลเดาจากชนิดพื้นหลังเพียงอย่างเดียว
5. **ประเมินรายชนิดพร้อมช่วงความเชื่อมั่น:** precision, recall, mAP@0.5/mAP@0.5:0.95 และ false positives ต่อภาพ/สไลด์; แยกตามอุปกรณ์ วิธีเตรียม ภาพคุณภาพต่ำและ low-intensity หากประเมินระดับผู้ป่วยต้องมี reference standard และรายงาน sensitivity/specificity/PPV/NPV แยกจาก mAP กำหนดขนาดชุดทดสอบร่วมกับอาจารย์/นักสถิติจากความกว้างช่วงความเชื่อมั่นที่ต้องการ
6. **นำเข้าแอพเมื่อผ่านการทดสอบ:** เปิดใช้เฉพาะคลาสที่มีข้อมูลและหลักฐานผลจริง มีผลไม่แน่ใจ/ภาพคุณภาพต่ำและมนุษย์ตรวจยืนยัน ไม่พบไข่ในหนึ่งรูปไม่ได้ยืนยันว่าไม่มีการติดเชื้อ ค่า confidence ไม่ใช่ความน่าจะเป็นที่ผู้ป่วยเป็นโรค
7. **ทดสอบออฟไลน์ภายหลัง:** export โมเดลที่ผ่าน validation เป็นรูปแบบเหมาะกับอุปกรณ์ เช่น ONNX แล้วทดสอบ output หลัง export/quantization, RAM และเวลาบนโทรศัพท์จริง การ cache หน้าเว็บ/Atlas ไม่ทำให้ API ตรวจภาพประมวลผลออฟไลน์โดยอัตโนมัติ

**ผลที่คาดหวังได้ในระยะถัดไป:** registry ที่สิทธิ์ครบ, ชุดภาพเต็มพร้อมกรอบที่ผู้เชี่ยวชาญยืนยัน, baseline detector และผลทดสอบรายคลาสบนข้อมูลที่ไม่รั่วไหล จึงค่อยพิจารณาการอ้างประโยชน์ทางคลินิก ยังระบุความแม่นยำไม่ได้ก่อนทดสอบภายนอก และยังไม่ยืนยันการตรวจครบ 8 กลุ่ม ณ ตอนนี้

## 6. ขอบเขตการตรวจสอบและไฟล์ประกอบ

ตรวจหน้า README/configuration/manifests จาก GitHub ของผู้วิจัย/สถาบันได้โดยตรง รวมทั้งขนาดตัวอย่าง LIDS บางภาพ ไม่ได้ดาวน์โหลด microscopy corpus ทั้งหมดหรือฝึกโมเดล หลายเว็บไซต์ต้นทางรวม DataPort, Kaggle, Mendeley และ publisher ถูก proxy ตอบ CONNECT 403 ก่อน TLS จึงแยก “หลักฐานที่อ่านได้” ออกจาก “ต้นทางที่ยังต้องเปิดตรวจ” อย่างชัดเจน การติดข้อจำกัดเครือข่ายนี้ไม่ใช่หลักฐานว่าลิงก์สาธารณะเสีย

- [dataset_catalog.csv](dataset_catalog.csv): ทะเบียนต้นทาง/หลักฐาน คลาส จำนวนและหน่วย annotation สิทธิ์ สถานะดาวน์โหลด บทบาท และช่องว่าง metadata สำหรับติดตามต่อ
- แหล่งอ้างอิงต้นทางและหลักฐานที่อ่านได้เชื่อมไว้ในแต่ละหัวข้อข้างต้น; ไม่ถือว่าหน้าเว็บที่เข้าถึงไม่ได้ได้รับการตรวจสดแล้ว

ไม่มีการติดต่อบุคคลภายนอก ดาวน์โหลดข้อมูลจำนวนมาก แก้โค้ดแอพ หรือเปลี่ยนสถานะโมเดลจากการทำรายงานฉบับนี้
