# การปรับ HelpMinths ตามข้อเสนอแนะอาจารย์ที่ปรึกษา

วันที่จัดทำ 25 ตุลาคม 2569 (2026) • ใช้ข้อเสนอแนะในเอกสารวิเคราะห์ที่ผู้ใช้แนบเป็นรายการปรับต้นแบบ ไม่เผยแพร่ชื่อหรือรหัสนักศึกษาในเอกสารแนบ

## รายการปรับและหลักฐานที่ต้องเก็บ

| ข้อเสนอแนะ | การปรับต้นแบบ | หลักฐานจากการใช้งานจริงที่ยังต้องเก็บ |
|---|---|---|
| HMW และการกำหนดปัญหา | หน้าโครงงานแสดง problem statement, HMW และกลุ่มผู้ใช้ | ทบทวนความตรงของปัญหาจากผู้ใช้เป้าหมาย |
| Empathize, persona, journey map | แสดง persona/journey แบบสมมติฐานและแบบบันทึกสัมภาษณ์ | สัมภาษณ์จริง บันทึกรหัสผู้เข้าร่วมและสิ่งที่สังเกต ไม่สร้างบทสัมภาษณ์ย้อนหลัง |
| Design Thinking เป็นระบบ | แสดง Empathize–Define–Ideate–Prototype–Test ทางเลือกก่อนเลือกเว็บ/YOLO และ MVP แต่ละระยะ | เชื่อมข้อค้นพบแต่ละรอบกับการเปลี่ยนต้นแบบ |
| ทดสอบ Atlas กับนักศึกษา 3–5 คน | เครื่องมือเริ่ม/หยุดเวลาและบันทึกผลสำเร็จของงาน | ผู้เข้าร่วมจริงและเวลาที่วัดจริง เป้าหมายไม่ใช่ยอดที่ทดสอบแล้ว |
| ทดลองอัปโหลดภาพจริง 5–10 ภาพ | บันทึกเหตุการณ์เตรียมภาพที่เกิดขึ้นจริงเฉพาะการทดสอบที่ยินยอม | รายงานจำนวนและผล upload workflow แยกจากความแม่นยำโมเดล |
| SUS 10 ข้อ | แบบตอบ 1–5 ครบ 10 ข้อ พร้อมสูตรคะแนน 0–100 | คำตอบจริงหลังใช้ต้นแบบ ระบุจำนวนชุดสมบูรณ์และคำแปลไทยที่ยังไม่ผ่านการตรวจสอบ |
| Feedback และปรับ 1–2 จุด | บันทึก feedback ประเด็นปรับปรุง สถานะ และหลักฐานการแก้ | ความเห็นจริงและการตรวจซ้ำหลังแก้ ไม่ใช้ข้อเสนอของผู้พัฒนาแทนคำตอบผู้เข้าร่วม |
| ความยั่งยืนหลังโครงงานจบ | บทบาทดูแลเว็บ/ข้อมูล/โมเดล การสำรองและจัดรุ่น แผนส่งมอบ | แต่งตั้งผู้รับผิดชอบจริงและตรวจการกู้คืน |
| แผนเพิ่มชนิด | แยก Atlas 12 รายการออกจากข้อมูลเริ่มต้นที่ผู้ใช้ส่ง 3 กลุ่ม และคลาสโมเดลที่ผ่านการประเมิน | ข้อมูลและการประเมินรายกลุ่มก่อนเปิดให้โมเดลรายงานชนิดเพิ่ม |
| การนำไปใช้จริง | แสดงจุดตรวจข้อมูล สิทธิ์ reference standard ชุดทดสอบอิสระ การทบทวนโดยมนุษย์ และการกำกับของหน่วยงาน | การอนุมัติ/การศึกษา/ข้อกำหนดที่เหมาะกับบริบทจริง ไม่อ้างว่าต้นแบบได้รับการรับรองแล้ว |
| ค่าใช้จ่ายและ Render free tier | เครื่องคำนวณต้นทุนตามสมมติฐานและลิงก์เอกสารผู้ให้บริการ | ราคาปัจจุบัน ภาระงานจริง เวลา inference และทรัพยากรที่วัดได้ |
| อ้างอิงในรายงานและ slide | ใช้บรรณานุกรมร่วมกันพร้อมแหล่งที่มาและขอบเขตการอ้าง | ตรวจรายการ 9 งานที่รายงานเดิมกล่าวถึงเมื่อได้รับบรรณานุกรมจริง |
| Capture หน้าจอในรายงาน | ใช้ภาพหน้าจอที่จับจาก build ของต้นแบบพร้อมคำอธิบายโหมดสาธิต/ข้อมูลจริง | ทบทวนภาพให้ตรงกับรุ่นที่นำเสนอและไม่รวมภาพผู้ป่วยโดยไม่จำเป็น |

ตารางนี้เป็นรายการตอบสนองต่อคำแนะนำ ไม่ใช่รายงานว่าผ่านการทดสอบกับผู้ใช้แล้ว ผลตรวจอัตโนมัติและไฟล์ประกอบของรุ่นนี้อยู่ในหัวข้อถัดไป โดยแยกจากผลผู้ใช้จริง

## วิธีอ่านผลอย่างตรงไปตรงมา

- ค่าจากการทดสอบใช้งานเริ่มจากไม่มีข้อมูล ไม่ใส่เวลา คะแนน SUS หรือคำพูดผู้เข้าร่วมตัวอย่างเป็นผลจริง
- SUS ต้องตอบครบ 10 ข้อ สูตรข้อคี่ = คำตอบ − 1 ข้อคู่ = 5 − คำตอบ แล้วรวม × 2.5 ได้ช่วง 0–100 ไม่ใช่ร้อยละความพึงพอใจ และไม่ใช่ความแม่นยำ AI
- การทดสอบนักศึกษา 3–5 คนเหมาะค้นหาปัญหา usability ในรอบต้น ไม่แทนการสรุปผลต่อประชากรหรือรับรองประสิทธิภาพทางคลินิก
- การอัปโหลดผ่านและการดู bounding box ได้เป็นผลทดสอบ workflow ต้องแยกจาก sensitivity/precision ของโมเดลซึ่งต้องมีข้อมูลอิสระและ reference standard
- Persona และ journey ก่อนสัมภาษณ์เป็นสมมติฐาน การมีฟอร์มสัมภาษณ์ไม่แปลว่าได้ทำ Empathize กับคนจริงแล้ว
- การมีรายการ Atlas 12 กลุ่มไม่ได้แปลว่า AI ตรวจครบ 12 กลุ่ม และข้อมูลที่รับรองเบื้องต้น 3 ภาพยังไม่ทำให้มีชุดทดสอบภายนอก
