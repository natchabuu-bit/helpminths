# เก็บบัญชี HelpMinths บน Supabase โดยใช้ Render Free

แนวทางนี้ให้ Render Free รันเว็บและบริการตรวจภาพตามเดิม ส่วนบัญชี รหัสผ่านที่แฮชแล้ว บทบาท สถานะอนุมัติ session และเอกสารรายการตรวจอยู่ใน PostgreSQL ภายนอก บัญชีจึงไม่ขึ้นกับไฟล์ชั่วคราวของเครื่อง Render เมื่อสมัครและอนุมัติแล้ว ผู้ใช้กลับมาเข้าสู่ระบบด้วยบัญชีเดิมได้ แม้ Render สร้างเครื่องใหม่

ไฟล์ [`render.supabase.yaml`](../../render.supabase.yaml) เป็นเทมเพลตทางเลือกของบริการ Free ไม่ได้สร้างโครงการ Supabase หรือเชื่อมฐานข้อมูลจริงให้เอง เจ้าของต้องสร้างโครงการและตั้งค่าลับใน Render ก่อนใช้โค้ดรุ่นที่รองรับ PostgreSQL

## ขอบเขตที่เก็บถาวร

| ข้อมูล | ที่เก็บเมื่อเปิด PostgreSQL |
|---|---|
| ชื่อบัญชี ข้อมูลสมัคร password hash บทบาท และสถานะอนุมัติ | PostgreSQL ในโครงการ Supabase |
| เจ้าของระบบและตัวบันทึกการตั้งค่ารหัสผ่านจากโฮสต์ | PostgreSQL |
| session และการยืนยันผู้เชี่ยวชาญ | PostgreSQL โดยยังมีวันหมดอายุตามกฎเดิม |
| เอกสารผล AI ผลทบทวน การส่งต่อ ข้อความ การแจ้งเตือน และ audit | PostgreSQL |
| ไฟล์ภาพที่อัปโหลด ภาพคลังหลังบ้าน และภาพเพิ่มเติม | ยังอยู่บนพื้นที่ไฟล์ส่วนตัวของ Render ซึ่งเป็นพื้นที่ชั่วคราวบน Free |

**การเชื่อมฐานข้อมูลครั้งนี้แก้การสูญหายของบัญชีและสถานะอนุมัติ ยังไม่ได้ทำให้ไฟล์ภาพถาวร** เอกสารผลตรวจอาจยังอยู่แต่เปิดไฟล์ภาพเดิมไม่ได้หลังเครื่อง Render ถูกสร้างใหม่ ต้องเชื่อมที่เก็บไฟล์ภายนอกแยกต่างหากก่อนถือว่าประวัติพร้อมภาพเก็บได้ครบระยะยาว การตั้ง `HELPMINTHS_STORAGE_DURABLE=1` ไม่ได้สร้างพื้นที่เก็บภาพให้

## สร้างโครงการ Supabase Free

1. เปิด <https://supabase.com/dashboard> สมัครหรือเข้าสู่ระบบของเจ้าของโครงการ
2. สร้างโครงการใหม่ในองค์กรของตน เลือกแผน Free และตรวจว่าไม่มี add-on ที่มีค่าใช้จ่าย
3. ตั้งชื่อโครงการ เช่น `helpminths` และตั้งรหัสผ่านฐานข้อมูลที่คาดเดายาก เก็บไว้ในตัวจัดการรหัสผ่าน รหัสนี้เป็นรหัสฐานข้อมูล ไม่จำเป็นต้องตรงกับรหัสบัญชี Super Admin ในเว็บ
4. เลือกภูมิภาคใกล้บริการ Render ถ้ามีตัวเลือกและ Render อยู่เอเชีย อาจเลือก Singapore เพื่อลดเวลาเชื่อมต่อ
5. รอให้โครงการพร้อมใช้งาน แล้วเปิด **Connect** เพื่อดู PostgreSQL connection string
6. เลือก **Session pooler** และคัดลอก URI ที่ Supabase แสดง วิธีนี้เหมาะเมื่อเครื่องโฮสต์เข้าฐานข้อมูลผ่าน IPv4; ใช้ host และชื่อผู้ใช้จากหน้าจอโครงการจริง ไม่เดารูปแบบเอง

ตัวอย่าง URI ต่อไปนี้เป็นเพียงรูปแบบ มีค่าตัวอย่างทั้งหมด:

```text
postgresql://postgres.PROJECT_REF:ENCODED_DATABASE_PASSWORD@POOLER_HOST:5432/postgres?sslmode=require
```

แทนค่ารหัสผ่านเฉพาะในช่องรหัสผ่านของ URI หากมีอักขระพิเศษ เช่น `@`, `:`, `/`, `#` หรือ `%` ต้องเข้ารหัสแบบ URL เฉพาะส่วนนั้นตามรูปแบบ connection string ห้ามนำ URI ที่ยังมีข้อความ `[YOUR-PASSWORD]` มาใช้จริง

Session pooler ปกติใช้พอร์ต 5432 หากใช้ Transaction pooler ให้ใช้ URI และพอร์ตที่ Supabase แสดงจริง อะแดปเตอร์ฐานข้อมูลปิดการใช้ prepared statements สำหรับการเชื่อมต่อผ่าน pooler และใช้ TLS สำหรับปลายทางภายนอก

ไม่ต้องนำ anon key หรือ service-role key ไปใส่หน้าเว็บ การเชื่อมต่อนี้ใช้ PostgreSQL จาก backend เท่านั้น และการสมัคร/อนุมัติผู้ใช้ยังทำใน HelpMinths ตามเดิม ไม่ต้องสร้างผู้ใช้ HelpMinths ทีละคนในหน้า Authentication ของ Supabase

## สำรองบัญชีเดิมก่อน deploy หรือเปลี่ยนตัวแปร

หากบริการปัจจุบันยังมีบัญชีหรือข้อมูลที่ต้องเก็บ ให้สำรองจากเครื่องบริการเดิมก่อน deploy/restart หรือเปลี่ยนการเชื่อมฐานข้อมูล ฐานข้อมูลชั่วคราวอาจหายระหว่างเปลี่ยนรุ่น

- สำรอง SQLite พร้อมไฟล์ภาพอย่างสอดคล้องกัน โดยหยุดการเขียนข้อมูลตามวิธีที่โฮสต์รองรับ หรือใช้กระบวนการสำรองออนไลน์ที่ควบคุมให้ฐานข้อมูลกับไฟล์ตรงกัน
- Render Free อาจไม่มี Shell/SSH จึงต้องตรวจช่องทางดึงข้อมูลที่บริการปัจจุบันรองรับ อย่าถือว่าคำสั่งในเครื่องส่วนตัวอ่านฐานข้อมูล live ของ Render ได้
- เก็บชุดสำรองในพื้นที่ส่วนตัว ไม่นำฐานข้อมูล password hashes ภาพส่วนตัว หรือ connection string จริงขึ้น GitHub หรือส่งในแชท
- ZIP สำรองโค้ดไม่ได้มีฐานข้อมูลบัญชีของบริการ บัญชีที่หายไปแล้วกู้จากโค้ดอย่างเดียวไม่ได้

หากมีสำเนา SQLite ส่วนตัวที่ถูกต้อง ให้ย้ายตามขั้นตอนถัดไป **ให้เสร็จก่อนเริ่มแอพบนฐานข้อมูลปลายทาง** เพราะแอพอาจสร้าง Super Admin โดยอัตโนมัติและทำให้ปลายทางไม่ว่างจนเครื่องมือปฏิเสธการย้าย ถ้าเริ่มจากฐานข้อมูลว่างใหม่และไม่มีข้อมูลเดิมให้ย้าย ให้ไปขั้นตั้งค่า Render โดยยอมรับว่าบัญชีเก่าที่สูญหายจะไม่กลับมาเอง

## ย้ายข้อมูลเดิมเข้า PostgreSQL

รันจากเครื่องผู้ดูแลที่มีโค้ดรุ่นนี้และติดตั้ง backend dependencies แล้ว โดยชี้ไปยังสำเนาฐานข้อมูลส่วนตัวที่ควบคุมการเขียนไว้:

```sh
python -m backend.platform.migrate_postgres --source /private/path/helpminths.sqlite3 --check
```

`--check` ตรวจฐานข้อมูลต้นทางอย่างเดียว ไม่เชื่อมฐานข้อมูลภายนอก ตั้ง `HELPMINTHS_DATABASE_URL` ใน environment ส่วนตัวของกระบวนการที่จะรัน migration โดยไม่ใส่ URI หรือรหัสผ่านใน command-line argument แล้วรัน:

```sh
python -m backend.platform.migrate_postgres --source /private/path/helpminths.sqlite3 --confirm-source-stopped
```

เครื่องมือรับเฉพาะฐานข้อมูลปลายทางที่ยังไม่มีข้อมูล หากมีบัญชีหรือเอกสารอยู่แล้วจะปฏิเสธ ไม่ล้างหรือเขียนทับให้ การย้ายเก็บรหัสบัญชี password hash ข้อมูลสมัคร บทบาท สถานะอนุมัติ เอกสาร และ audit ภายใน transaction เดียว แต่ไม่ย้าย session เดิม ทุกคนต้องเข้าสู่ระบบอีกครั้งด้วยบัญชีเดิม และผู้เชี่ยวชาญต้องยืนยันรหัสผ่านตามกฎเดิม

คำสั่งนี้ไม่ได้ย้ายไฟล์ `images/` หรือ `archive-images/` ไปที่เก็บภาพภายนอก ต้องจัดเก็บไฟล์เหล่านั้นแยกตามขอบเขตด้านบน ตรวจผลสรุปจำนวนรายการของการย้ายและเก็บชุดสำรองต้นทางไว้จนตรวจรับครบ

## เชื่อมบริการ Render เดิม

หลังสำรอง/ย้ายข้อมูลที่ต้องเก็บเรียบร้อยแล้ว:

1. เปิด Render Dashboard และเลือกบริการ `helpminths` เดิม คง instance plan เป็น Free ไม่ต้องเพิ่ม Persistent Disk
2. ใช้รุ่นโค้ดที่รองรับ PostgreSQL ในขั้นตอนนี้ หากเป็นบริการเดิมให้ตั้งค่าในบริการเดิม ไม่สร้างบริการชื่อซ้ำจาก Blueprint โดยไม่ตั้งใจ
3. เปิด **Environment** และตั้งค่า:

| ตัวแปร | ค่า |
|---|---|
| `HELPMINTHS_DATABASE_BACKEND` | `postgres` |
| `HELPMINTHS_DATABASE_URL` | PostgreSQL URI จาก Supabase Connect พร้อมรหัสผ่านจริง เก็บเป็นค่าลับใน Render เท่านั้น |
| `HELPMINTHS_AUTO_STORAGE` | `1` สำหรับโฟลเดอร์ภาพส่วนตัวชั่วคราวของ Docker ตามเดิม |

4. คง `HELPMINTHS_SUPER_ADMIN_PASSWORD` และชื่อเจ้าของ โมเดล และค่าด้านแดชบอร์ดที่ใช้อยู่เดิม ไม่ใส่ URI ลงตัวแปร `VITE_*` เพราะค่ากลุ่มนี้ถูกฝังใน frontend
5. ถ้าไม่มีพื้นที่เก็บไฟล์ถาวรจริง อย่าตั้ง `HELPMINTHS_STORAGE_DURABLE=1` เพื่ออ้างว่าไฟล์ภาพถาวร
6. บันทึกและ deploy โค้ดรุ่นที่ทดสอบแล้วตามวิธีที่ Render แสดง รอให้บริการพร้อมและตรวจ logs เฉพาะสถานะทั่วไป ไม่เผยแพร่ค่าลับ

ตัวเลือก `render.supabase.yaml` คงแผน Free และกำหนด `HELPMINTHS_DATABASE_URL` เป็นค่าที่เจ้าของต้องกรอกส่วนตัว ไม่มี URI จริงใน repository ไฟล์นี้ไม่ได้สร้างโครงการ Supabase หรือซื้อทรัพยากรให้

เมื่อเลือก backend `postgres` แล้ว แต่ URL หาย ใช้ไม่ได้ หรือเชื่อมต่อไม่ได้ ระบบต้องแจ้งข้อขัดข้องและหยุดการทำงานส่วนที่ต้องใช้ฐานข้อมูล ไม่เปลี่ยนไปสร้าง SQLite ว่างในเครื่องชั่วคราวเงียบ ๆ เพราะจะทำให้ดูเหมือนบัญชีหายและชวนสมัครซ้ำ

## ตรวจหลังเชื่อม

1. ถ้าย้ายข้อมูลเดิม ให้เข้าสู่ระบบด้วยบัญชีเดิม ตรวจชื่อ บทบาท สถานะอนุมัติ และประวัติข้อความที่เกี่ยวข้อง
2. ถ้าเริ่มฐานข้อมูลใหม่ ให้ตรวจบัญชี Super Admin ตามการตั้งค่าลับเดิม จากนั้นสมัคร/อนุมัติผู้ใช้ครั้งเดียวบนฐานข้อมูลใหม่นี้
3. เปิด `/api/platform/status` ของบริการและตรวจว่า `database_backend` เป็น `postgres`, `accounts_persistent` เป็น `true` และ `storage.database_durable` เป็น `true` สำหรับ Render Free ที่ยังไม่ได้เชื่อมที่เก็บภาพแยก `storage.images_durable` ต้องเป็น `false` และ `storage.mode` เป็น `mixed` ไม่อ่านสถานะพื้นที่ภาพแทนสถานะฐานข้อมูล ตรวจด้วยว่ามีตารางใน schema `helpminths` ของโครงการที่ตั้งใจใช้
4. Restart บริการ Render แล้วทดสอบเข้าสู่ระบบด้วยบัญชีเดิมอีกครั้ง ต้องยังมีรหัสบัญชี บทบาท และการอนุมัติเดิม ไม่ต้องสมัครใหม่
5. ทดสอบหลัง deploy ใหม่ด้วย แล้วตรวจว่าข้อความและเอกสารเดิมยังอยู่ ขอบเขตไฟล์ภาพยังเป็นไปตามตารางข้างต้น
6. เมื่อ session หมดอายุ ผู้ใช้เข้าสู่ระบบใหม่ได้ด้วยชื่อและรหัสผ่านเดิม การหมดอายุ session ไม่ลบบัญชี กฎยืนยันผู้เชี่ยวชาญ 15 นาทีและสิทธิ์เข้าถึงภาพคงเดิม

## ความเป็นส่วนตัวและการดูแล

ตารางแอพอยู่ใน schema ส่วนตัว `helpminths` แยกจาก schema `public` ที่อาจเปิดผ่าน Data API ของ Supabase ตามค่าเริ่มต้น อย่าเพิ่ม `helpminths` เป็น exposed schema หรือเปิดสิทธิ์อ่านตารางบัญชีให้ anonymous/API roles ข้อมูลส่วนตัวอ่านผ่าน backend HelpMinths ที่ตรวจสิทธิ์เดิม

connection string เป็นสิทธิ์ฐานข้อมูลของ backend ต้องอยู่ใน Render Environment/secret ของผู้ดูแลเท่านั้น ไม่เก็บใน browser, localStorage, frontend source, URL แชร์ หรือ Git ถ้าต้องเปลี่ยนรหัสฐานข้อมูล ให้อัปเดตค่าลับและ deploy ตามวิธีของบริการ

แผนฟรีมีโควตาและนโยบายพักโครงการเมื่อไม่ใช้งานตามเงื่อนไขของผู้ให้บริการ ณ เวลาที่สมัคร หากโครงการถูกพัก ต้องเปิดโครงการกลับใน Supabase ก่อนระบบจะเชื่อมได้ ไม่แก้โดยลบตัวแปรฐานข้อมูลเพื่อให้แอพสร้างฐานข้อมูลใหม่ ข้อมูลไม่รับประกันว่าจะอยู่ตลอดไปหากโครงการถูกลบ บัญชีผู้ให้บริการถูกปิด หรือไม่มีสำรอง จึงควรสำรอง PostgreSQL และทดสอบ restore ในพื้นที่ส่วนตัวเป็นระยะ

เอกสารนี้อธิบายการเชื่อมระบบ ไม่ใช่หลักฐานว่าโครงการ Supabase ของเจ้าของถูกสร้าง เชื่อม หรือ deploy บนบริการออนไลน์แล้ว ต้องตรวจรับบนบริการจริงหลังเจ้าของตั้งค่าลับครบ
