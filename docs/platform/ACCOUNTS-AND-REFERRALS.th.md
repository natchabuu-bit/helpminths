# บัญชี ประวัติรายวัน และภาพส่งต่อผู้เชี่ยวชาญ

## วิธีใช้

1. กด **เข้าสู่ระบบ** ด้านบน → **สมัครสมาชิก** ตั้งชื่อบัญชีและรหัสผ่านอย่างน้อย 12 ตัวอักษร พร้อมยืนยันรหัสผ่าน บัญชีที่สมัครเองเป็นผู้ใช้ทั่วไป ไม่มีช่องเลือกสิทธิ์ผู้เชี่ยวชาญเอง
2. ใน **ตั้งค่าและบัญชี** เปลี่ยนชื่อบัญชีหรือรหัสผ่านได้ โดยยืนยันรหัสผ่านปัจจุบันก่อน บัญชีเดิมยังเป็นเจ้าของผลตรวจ และเซสชันบนอุปกรณ์อื่นจะถูกยกเลิก
3. เปิด **ตรวจวิเคราะห์** เพิ่มภาพและกรอกรหัสตัวอย่างนิรนาม ตรวจคุณภาพแล้ววิเคราะห์ เมื่อสำเร็จ ระบบบันทึกภาพและผลเข้าประวัติของบัญชีโดยอัตโนมัติ ไม่ต้องดาวน์โหลด JSON
4. เมื่อไม่มั่นใจ กรอก **สิ่งที่ต้องการให้ผู้เชี่ยวชาญช่วยตรวจ** ใต้ผลตรวจ แล้วกด **ส่งให้ผู้เชี่ยวชาญ** ภาพจะอยู่ใน **ทบทวนโดยผู้เชี่ยวชาญ → ภาพรอผู้เชี่ยวชาญ** เฉพาะผู้ส่งและผู้มีสิทธิ์ตรวจเท่านั้นที่เปิดภาพได้
5. ผู้ดูแลตรวจสอบตัวบุคคลและคุณสมบัติวิชาชีพนอกระบบก่อน แล้วอนุมัติบทบาท **ผู้เชี่ยวชาญ** ใน **ตั้งค่าและบัญชี → จัดการผู้ใช้** การเปลี่ยนบทบาทยกเลิกเซสชันเดิม ต้องเข้าสู่ระบบใหม่
6. ผู้เชี่ยวชาญเข้าสู่ระบบ เปิดเมนูทบทวน แล้วยืนยันรหัสผ่านอีกครั้งเพื่อปลดล็อกคลังภาพครั้งละไม่เกิน 15 นาที นี่คือการยืนยันรหัสผ่านซ้ำ ไม่ใช่การตรวจคุณสมบัติวิชาชีพอัตโนมัติหรือ MFA
7. เปิดภาพ ตรวจทั้งภาพ ยืนยัน/แก้ชนิดและกรอบ/เพิ่มกรอบตกหล่น เขียนคำตอบ เลือก **ทบทวนครบแล้ว** และยืนยันว่าได้ตรวจทั้งภาพก่อนบันทึก หากยังสรุปไม่ได้ให้ขอทบทวนเพิ่มเติม
8. เจ้าของภาพเปิด **ตอบกลับแล้ว** เพื่ออ่านคำตอบ ผลที่ยืนยันแล้วกลับไปอยู่ใน **ประวัติการตรวจ** ของวันตรวจเดิมตามเวลาไทย ไม่สร้างผลตรวจซ้ำหรือเขียนทับคำทำนาย AI

ประวัติมีปุ่มวันนี้ ทุกวัน วันที่ย้อนหลัง 31 วันที่มีข้อมูล และตัวกรองละเอียด ภาพรอตรวจ/กำลังตรวจ/ขอข้อมูลเพิ่มแยกอยู่ในคลังส่งต่อ ไม่รวมในประวัติรายวันปกติ ผลสาธิตแยกจากผลจริงและส่งให้ผู้เชี่ยวชาญไม่ได้

## รูปแบบภาพ

เลือกไฟล์ได้ทุกนามสกุล แต่ต้องเป็นข้อมูลภาพราสเตอร์จริงที่ตัวถอดรหัสอ่านได้ เช่น JPEG/JPEG2000, PNG, HEIC/HEIF, AVIF, TIFF, BMP, GIF, WebP, ICO, PPM และรูปแบบอื่นตาม `GET /api/images/formats` การเปลี่ยนนามสกุลไม่ทำให้เอกสารหรือไฟล์เสียกลายเป็นภาพ

- สูงสุด 20 MiB และ 40 ล้านพิกเซล ไม่ย่อหรือตัดภาพเงียบ ๆ
- GIF/WebP ใช้เฟรมเริ่มต้นเป็นภาพนิ่ง ภาพหลายหน้าทางเซิร์ฟเวอร์ใช้หน้าแรก มีข้อความแจ้งเมื่อแปลง
- TIFF 16 บิตแปลงเต็มช่วงเป็น 8 บิตเพื่อใช้กับโมเดล พร้อมข้อความแจ้ง; TIFF 32 บิต/float, RAW/DNG, SVG, PDF และ EPS ต้องส่งออกเป็นรูปแบบที่รองรับก่อน
- รูปแบบที่เบราว์เซอร์เปิดไม่ได้ เช่น HEIC/TIFF ส่งไปแปลงเป็น PNG ผ่านบริการเดียวกับเว็บ โดยไม่สร้างรายการ ไม่บันทึกภาพ และไม่เรียก AI การแปลงนี้ต้องเชื่อมบริการได้ ภาพที่เบราว์เซอร์เปิดเองได้ยังดูออฟไลน์ได้
- หาก PNG หลังแปลงเกิน 20 MiB ให้ลดความละเอียด/ส่งออกใหม่ การแก้ EXIF orientation ทำก่อนประมวลผล ภาพที่จัดเก็บไม่มี EXIF/GPS

## Render Free และพื้นที่จัดเก็บถาวร

Render Free ไม่มี Persistent Disk สำหรับบริการเว็บนี้ การตั้ง `HELPMINTHS_DATA_DIR` อย่างเดียวไม่ได้สร้างพื้นที่ถาวร บัญชี ภาพ และประวัติอาจหายเมื่อ restart หรือ deploy หากใช้ filesystem ชั่วคราว จึงยังไม่เปิดฐานข้อมูลบนบริการปัจจุบันโดยอัตโนมัติ และไม่ได้เปลี่ยนแผนหรือซื้อบริการใด

โค้ดพร้อมใช้กับ SQLite และโฟลเดอร์ภาพส่วนตัวบนพื้นที่ถาวรที่ mount ได้ หากต้องการออนไลน์ ให้ใช้โฮสต์/แผนที่มี volume แล้วตั้ง:

| ตัวแปร | ค่าที่ต้องตั้ง |
| --- | --- |
| `HELPMINTHS_DATA_DIR` | พาธบน volume จริง เช่น `/var/data/helpminths` เมื่อ mount ที่ `/var/data` |
| `HELPMINTHS_STORAGE_DURABLE` | `1` หลังเชื่อม volume จริงแล้ว เป็นคำประกาศ ไม่ใช่การสร้าง disk |
| `HELPMINTHS_COOKIE_SECURE` | `1` สำหรับเว็บ HTTPS |
| `HELPMINTHS_ADMIN_SETUP_TOKEN` | รหัสสุ่มลับ 32–256 ตัวอักษร สำหรับตั้งผู้ดูแลครั้งแรกทางเว็บ ใช้เป็น secret บนโฮสต์ |

บริการฐานข้อมูล/ที่เก็บภาพภายนอกแบบฟรีต้องเพิ่ม adapter และตั้งค่าบริการนั้น ระบบปัจจุบันยังไม่ได้เชื่อม Supabase, Google Drive หรือ object storage เป็นฐานข้อมูลบัญชี ไม่สามารถตั้ง URL ของบริการเหล่านั้นลงในตัวแปรพาธแล้วใช้งานได้ทันที

ทางเลือกที่ไม่ต้องซื้อโฮสต์คือรันบนคอมพิวเตอร์ของตนเอง เก็บ `HELPMINTHS_DATA_DIR` ในโฟลเดอร์ส่วนตัวนอก `public/`, `dist/` และ Git สำรองฐานข้อมูลกับภาพ ใช้ `HELPMINTHS_COOKIE_SECURE=0` เฉพาะการพัฒนาบน localhost; เว็บที่เปิดผ่านอินเทอร์เน็ตต้องใช้ HTTPS

## ตั้งผู้ดูแลครั้งแรก

เจ้าของโฮสต์สร้างรหัสสุ่มในเครื่อง เช่นคำสั่งนี้ แล้วนำผลไปตั้งเป็น secret **อย่าส่งรหัสนี้หรือรหัสผ่านในแชต/commit**:

```bash
python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

เมื่อฐานข้อมูลพร้อมและตั้ง secret แล้ว ให้เปิด **ตั้งค่าและบัญชี** ขณะยังไม่ได้เข้าสู่ระบบ จะเห็นแท็บ **ตั้งค่าผู้ดูแลครั้งแรก** กรอก secret พร้อมชื่อบัญชี/รหัสผ่านผู้ดูแลที่ต้องการ เส้นทางนี้ปิดเมื่อมีผู้ดูแลที่ใช้งานอยู่แล้ว ลบ secret ออกจาก environment หลังตั้งผู้ดูแลสำเร็จ การสมัครสมาชิกปกติไม่ให้สิทธิ์ผู้ดูแลแม้เป็นบัญชีแรก

หากใช้ terminal ได้ ยังคงใช้ `python -m backend.platform.bootstrap --username YOUR_ADMIN_NAME` และกรอกรหัสผ่านใน terminal ได้ ไม่มีบัญชี/รหัสผ่านเริ่มต้นฝังในโค้ด

## ตรวจหลัง deploy

เปิด **ตั้งค่าและบัญชี** ตรวจฐานข้อมูล พื้นที่ถาวร และโมเดล แล้วใช้ภาพทดสอบที่ไม่มีข้อมูลผู้ป่วยทดสอบสมัครสองบัญชี ตรวจภาพ ส่งต่อ อนุมัติผู้เชี่ยวชาญ ยืนยันรหัสผ่าน ตรวจยืนยัน และกลับมาอ่านคำตอบ/ประวัติ ตรวจว่าบัญชีอื่นเปิดภาพไม่ได้ก่อนใช้ข้อมูลจริง

การทำงานของบัญชีและการส่งต่อไม่ยืนยันความแม่นยำของโมเดล สิทธิ์บทบาทในแอปไม่ได้ตรวจคุณสมบัติวิชาชีพอัตโนมัติ และต้องสำรองข้อมูลนอก volume แยกต่างหาก
