## หน้าตรวจ

- รวมสถานะบริการ/โมเดล ออฟไลน์ และโหมดสาธิตเป็น `.scan-status-line` เดียว ภายในกรอบภาพ ใต้หัวกรอบและเหนือภาพหรือพื้นที่อัปโหลด
- ข้อมูลสาธิตยังระบุ **ข้อมูลสาธิต ไม่ใช่ผลตรวจจาก AI** อย่างชัดเจน และใช้ปุ่มลองเชื่อมต่อ/ใช้ภาพของคุณในแถวเดียวกัน
- เอาป้ายสถานะบนหัวหน้า แบนเนอร์สาธิตแยก และข้อความความพร้อมซ้ำในกล่องผลว่างออก คง error, การประเมินคุณภาพภาพ ข้อกำหนดบัญชี และคำเตือนลักษณะพยาธิไว้
- แถวสถานะตัดบรรทัดได้บนจอแคบหรือเมื่อขยายข้อความ ใช้ `role="status"` และ `aria-live="polite"` พร้อมปุ่มที่มี focus-visible
- `.scan-demo-banner` คงเป็น class ของแถวเดียวนี้เมื่อเป็นโหมดสาธิต เพื่อให้ตัวตรวจและสคริปต์เดิมยังชี้ไปยังข้อความสาธิตที่มองเห็นจริง ไม่มีแบนเนอร์แยกซ่อนอยู่
- ไม่เปลี่ยน logic อัปโหลด การเรียกตรวจภาพ เกณฑ์โมเดล บัญชี หรือการเช็กการเชื่อมต่อ ข้อมูลภาพยังไม่ถูกส่งตรวจอัตโนมัติเมื่อเชื่อมต่ออีกครั้ง

## Atlas

พบกรณีที่ทำซ้ำได้บนจอ 375px: เลื่อนรายการลงแล้วเปลี่ยนกลุ่มพยาธิ เบราว์เซอร์ยังยึดตำแหน่งเลื่อนเดิม ทำให้ด้านบนของรายการแรกในผลกรองใหม่ถูกตัดใต้ช่องกรอง การค้นหาก็เก็บตำแหน่งเดิมไว้เช่นกัน

- กลับไปจุดเริ่มรายการเมื่อเปลี่ยนคำค้นหรือกลุ่มพยาธิ
- การเลือกชนิดพยาธิยังรักษาตำแหน่งเลื่อนของรายการ
- ปิด scroll anchoring เฉพาะรายการ เพิ่มพื้นที่สำหรับกรอบโฟกัส และจัดรายการจากด้านบนโดยไม่ซ่อนผลลัพธ์หรือเปลี่ยนความสูงเพื่อกลบอาการ
- คงช่องค้นหา กลุ่มพยาธิ รายชื่อทุกชนิด และการเปิดภาพ/โมเดลเดิม

## Tests

- เพิ่ม regression tests ของสถานะเดียวเหนือภาพ การลองเชื่อมต่อ การคงภาพและไม่ส่งตรวจเอง รวมถึงรายการ Atlas หลังเลื่อนแล้วเปลี่ยนตัวกรอง/คำค้น
- กรณีข้อความ 200% ทดสอบการเลื่อนเอกสารให้ถึงแถวแรกก่อนตรวจว่ากดได้ โดยยืนยันว่าตำแหน่งเลื่อนภายในรายการยังเป็นศูนย์ และคงการตรวจแถวสุดท้ายจากการกด Tab จริงโดยไม่เลื่อนช่วย
- ปรับ assertion ของ E2E จากกล่องสถานะโมเดลเดิมมาที่แถวสถานะใหม่ โดยคงเงื่อนไขความพร้อมและ assertions ของโมเดล/ชีววิทยาเดิม
- เพิ่มการตรวจแถวสถานะในชุด offline และปรับชื่อหัวข้อหน้าแรกเก่าจากเฟส 3 ให้ตรงกับหน้าใหม่ คงการตรวจ cache ความเป็นส่วนตัว และการไม่ส่งภาพซ้ำอัตโนมัติ
